MusicServer 0.21.7 — 上传流程优化与永久删除

本版继续使用 schema 8，保留现有账户、密码、头像、播放器 Key、曲目 UUID、歌单、邮箱、配额及旧上传续传检查点。已运行 schema 8 的安装可在网页检查并确认更新，不需要重新导入数据库或重复维护更新器；升级后刷新网页。

新增与优化：

- 上传默认一次开始、自动校验入库，可选择“入库前确认”；统一传输、校验和结果汇总，失败任务单独重试。
- 默认1个文件传输，可选2个；传输与上一首服务端校验重叠，显示真实校验阶段，不使用虚构校验百分比。
- 续传、校验和正式音频优先复用同卷文件链接，支持复制回退、碰撞保护与中断恢复；重复曲目按服务端实际收到字节识别，保留原UUID、归属和资料，最终额度及标签版本继续复核。
- 单Worker计算分片摘要并保留HTTP／不支持Worker时回退；本地解析限为2项，任务列表每页50项，可筛选未完成、失败和完成任务。
- 支持批量作者／专辑、本批默认标签及目标歌单。音频已入库但加入歌单失败时，仅重试歌单操作；刷新后保留待重试草稿，无需重新选择或传输音频。
- 提交回执在同一事务保存24小时。确认响应丢失可恢复已提交结果，不重复应用标签。修复旧账户迟到响应、旧批次及附件重新解析影响新任务的边界。
- 管理员可在“曲库维护 → 已下架曲目”永久删除音频和歌单占位；普通下架继续保留文件及恢复能力。
- 用户管理新增“完全删除”：账户须已停用且没有管理曲目、原始上传曲目、歌单和上传暂存。历史已删除账户也可清理；释放登录名和邮箱，保留审计及公共标签贡献。接管不会绕过原始上传者保护。
- 上传带宽仍受实际线路限制；浏览器默认仅保存任务元数据，刷新后未完成的传输仍需选择原文件继续，不能承诺关闭浏览器后持续传输。

旧 schema 7 的 Linux/systemd 安装升级步骤：

1. 保存完整备份，先安装正式 0.20.3／schema 7 桥接主程序。
2. 使用已验签的 0.20.3 Linux 包，由用户执行其 `musicserver-updater -config /etc/musicserver/updater.json -refresh-worker 0.20.3`，核验能力支持 schema 7、8 及 7→8。
3. 完成后在网页检查并安装 0.21.7。新程序执行完整性／外键／空间预检、旧格式快照及事务迁移，失败按匹配旧程序／旧库回退。
4. latest 已前进时，按包内 `deploy/schema8-upgrade.md` 提交固定桥接版本；该指南包含验签及完整命令。不要用 bootstrap install.sh 覆盖已有安装，不让旧程序直接读取 schema 8 库。

首次安装直接使用 0.21.7。Windows 原有安装备份并停服后替换已验证程序，保留原数据启动，无 Linux root 工具维护步骤。历史 schema 1–6 或无版本库仍拒绝自动迁移，不要手改格式标记。

发布本身不操作实际服务器，维护及安装由用户自行执行。
