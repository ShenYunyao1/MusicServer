MusicServer 0.20.3 — 数据保留升级桥接版

本版保持 schema 7，为后续标签与组合筛选版本建立保留旧数据的升级路径。现有 0.20.2 服务器可先通过网页检查更新并确认安装；本次不升级数据库格式，不清库，不重新导入音频，账户、密码、Key、歌单、曲目 UUID、路径、邮箱状态及配额保留。

重要：本版尚不启用标签／组合筛选。相关功能已经通过隔离 schema 8 及新旧播放器 CI；正式启用必须先完成本桥接版主程序升级，以及经过单独授权的独立 root 更新器维护，再发布 schema 8 正式版。请勿手工修改数据库版本号或把测试预览作为正式程序安装。

- 增加有限的 7→8 迁移策略、签名清单迁移来源校验及更新器能力检查；未知或未支持的 schema 继续拒绝。
- 新增独立更新器的受控维护命令，必须使用已经验签、与已安装主程序同 schema 的正式桥接包，由 root 执行。网页更新主程序不会自动替换独立 root 更新器。
- 为未来跨格式启动增加数据库完整性、外键和磁盘空间预检，以及独立的迁移前旧格式快照。迁移采用事务，更新失败时恢复匹配的旧程序及旧库；手动替换程序也具备迁移前保护。
- 备份／恢复支持已知的事务迁移路径，保留原数据。音频重新扫描仅作为后续可选的标签整理步骤，不代替数据库迁移。
- 已验证正式 0.20.2 源码生成的非空库升级、真实非 root systemd 迁移与失败回退、网页备份及 CLI 恢复，以及两个固定 Windows 播放器分别对 schema 7／8 的原生联调。正式包不包含 schema 8 测试预览。

升级顺序：

1. 在服务器网页安装 0.20.3 并重启，核对版本及原有数据。正常重启后需重新登录，播放器 Key 保留。
2. 另行安排维护窗口，按包内 deploy/updater-maintenance.md 验证正式资产并维护独立更新器；该操作不是本次网页安装自动完成的步骤。
3. 维护及验收完成后，再安装后续正式标签版本；迁移会保留旧库快照和现有媒体。

云端不会因本版发行自动部署或重启。Windows 服务器继续按既有流程手动替换程序，Windows 播放器无需为本桥接版更新。
