# 音乐服务器 0.21.10

Go 1.26+，SQLite schema 8，HTTP API `/api/v2`，内置中文管理页。支持 Windows 和 Linux。

本版修复审计发现的存储、认证、同步、标签、备份及界面缺陷。已运行schema 8的安装可直接网页更新主程序，不重复迁移或重新导入媒体；0.21.10的独立更新器恢复修复还需维护者按[更新器维护说明](deploy/updater-maintenance.md)手动更新root worker，网页不会替换该工具。schema 7原库启动前自动校验、创建旧格式快照并事务升级，保留账户、Key、歌单和曲目身份；旧schema 7 Linux安装先完成0.20.3桥接与独立更新器维护，完整命令见[schema 8升级步骤](deploy/schema8-upgrade.md)。

固定产物路径、运行目录布局、编译打包与 Git 提交规则见 [服务器编译与运行目录规范](../Docs/服务器编译与运行目录规范.md)。

多用户功能范围见 [多用户版本开发方案与进度](../Docs/多用户版本开发方案与进度.md)。公开订阅见 [第一期计划](../Docs/公开歌单与订阅开发计划.md)，指定账户邀请见 [第二期计划](../Docs/指定账户只读分享开发计划.md)。本版支持公开及指定账户的只读分享，协作编辑后续实施。

前端功能分布见 [服务器前端布局重构计划与进度](../Docs/服务器前端布局重构计划与进度.md)，歌单新交互及验收见 [歌单显示交互与封面开发计划](../Docs/歌单显示交互与封面开发计划.md)。保留歌单封面、独立编辑和触屏排序，新增公开目录及订阅页签。

## 网页功能入口

- **个人中心**：右上角账户菜单进入，只读“基本资料／存储与上传／账户安全／登录管理”四页签。资料、邮箱和密码各自通过独立弹窗修改，关闭清理草稿及敏感输入；正常切换页面不误报未保存。容量额度在“存储与上传”查看，统计规则保持原始上传者语义。
- **个人头像**：个人中心 → 基本资料 → 编辑资料，选择JPEG／PNG并裁剪、缩放、预览，和昵称统一保存；恢复默认同样须保存。个人中心和顶部同步显示，头像纳入数据库备份，版本冲突保留草稿，不影响音频配额。
- **编辑标签词条**：标签器中标签旁“编辑”可直接修改名称和每行一个别名，保存后新别名立即匹配同一词条；也可从“标签词典”进入。管理员编辑公共词条，普通用户编辑自己的个人词条。
- **音乐**：全局曲库、公开歌单、我的歌单、上传任务。“我的歌单”分我创建的／我订阅的／分享邀请；自己创建的歌单整项点击打开，桌面拖拽或触屏长按调整顺序，右键／Shift+F10 打开编辑和删除菜单；搜索期间暂停排序。曲目显示封面、基础信息及个人备注，长按约 350ms 排序；订阅内容只读，允许添加本人备注。系统全局曲库不混入个人歌单列表。
- **标签与筛选**：全局曲库“筛选与分类”可组合公共／个人标签及曲目信息，按服务端完整结果计数和分页；“未标签”快捷筛选指没有公共标签。普通用户可为全站可见曲目打公共标签及创建词条，公共词条改名、别名、合并、删除和分组仍由管理员治理。右键“管理标签”打开不遮挡选择的标签器，支持别名搜索、回车创建、即时保存／撤销及固定对象；大批量保留任务确认。个人标签和保存条件不向其他用户或播放器 Key 开放。
- **播放器接入**：本人 API Key、授权和调用统计。空授权 Key 可以连接，但显示空库；全局曲库须显式授权。Key 行内的测试连接需要本次输入完整 Key，不保存明文。复制成功提示自动消失；一次性弹窗关闭即清空密钥。
- **管理概览**：仅管理员可见，展示实际读取的曲库与账户摘要，提供维护入口和全站调用统计。普通用户默认进入全局曲库，管理员默认进入管理概览。
- **用户管理**：账户列表进入独立用户详情，按当前管理曲目、原始上传、私人歌单和 Key 查看资源；启停、密码重置及停用账户的接管集中在用户详情。本人统计与管理员全站／指定账户统计使用独立范围。
- **曲库维护**：目录扫描、文件缺失、已下架曲目与恢复。文件缺失需要恢复实际文件并扫描；下架保留记录和歌单占位。
- **系统日志**：管理导航下独立页面，仅管理员会话可看，按级别／类别及请求编号筛选，支持分页、暂停和仅可见时五秒增量更新。记录服务启停、请求异常／耗时、扫描、上传阶段和更新请求；操作审计仍在“系统设置 → 操作记录”。
- **系统设置**：常规、容量与额度、备份与恢复、程序更新和操作记录。完整备份包含已入库媒体，仅数据库备份不含音频；下载升级包不等于安装；操作记录展示最近 100 条并在页面内分页。
- **账户菜单**：右上角进入个人中心（基本资料／账户安全／登录管理），原修改密码和登录管理入口直接跳转对应页签；退出为独立操作。手机使用导航抽屉，主要曲目、Key 与账户列表采用紧凑布局；曲目预览固定在底部，可暂停和关闭。

页面使用 `#/library`、`#/playlists/<id>`、`#/admin/users/<id>` 等地址，支持刷新和浏览器返回。普通曲库和私人歌单每页 50 项，搜索／筛选／页码随地址保留，曲目完整歌词按需读取。前台每 15 秒轻量检查修订号，有变化补取当前页，编辑和拖拽时延后；公开订阅／邀请继续使用实时通知。“未加入我的歌单”仅表示本人私人歌单没有引用，不代表无人收藏。

上传分为添加、校验预览、确认入库；音频按最多 4 MiB 的块顺序上传，支持暂停和继续，已确认检查点保留 24 小时。刷新或退出后可恢复任务及编辑元数据，浏览器不保存整首音频或重新打开本地文件的权限：需要时选择原文件，先校验大小和已上传前缀，再继续剩余部分；附件需重新选择或明确忽略。服务端校验预览仍有 30 分钟有效期。取消任务会清理暂存，确认入库后不再是临时任务。

“容量与额度”提供磁盘、分类占用、预留策略和安全清理；账户配额归入用户管理，列表只读展示，点击“调整额度”打开不限额／MiB／GiB 弹窗，用户详情沿用同一编辑入口，已删除账户集中显示历史用量。播放器 0.4.0 配合本版对象增量协议，普通成员增删或排序只补取缺少／变化的曲目信息；旧客户端和旧完整对象接口继续可用。实施和验收见 [本期计划](../Docs/容量布局与续传分页同步开发计划.md)。

歌单编辑使用 `#/playlists/<id>/edit` 独立页面，返回按钮位于正文左上角。可选择 JPEG、PNG、静态 WebP 原图，最大 8 MiB／2000 万像素；使用正方形裁剪框调整位置及缩放，输出最大 1024×1024 PNG。裁剪后先在本地预览，点击“保存修改”才一次提交名称、简介和封面；取消不改变原歌单，冲突保留草稿并提供重新载入。手机可从详情进入编辑，删除入口位于编辑页底部。

“新建歌单”使用 `#/playlists/new`，与编辑页共用名称、简介、可见性、封面预览和正方形裁剪表单，默认私有。点击“创建歌单”时通过 `POST /api/v2/playlists` multipart 表单（id／name／description／visibility／可选 cover）一次保存；成功后打开新歌单详情。取消、返回或仅裁剪预览不会创建记录，保存失败保留草稿供重试；新建页不显示删除和重新载入已有对象按钮。JSON 创建 API 保持可用。

新增 `PUT /api/v2/playlists/<id>/editor`，使用 multipart 表单 `name`、`description`、可选 `cover` 或 `remove_cover=true`，要求账户会话、CSRF 与当前 `If-Match`；提交图片为已裁剪的 PNG／JPEG 正方形，最大 1024px 和 8 MiB，服务端实际解码校验并拒绝动画。事务内保存封面资产、歌单版本、同步变更和审计，任意失败全部回滚。歌单的 `cover_id`、`cover_mime` 可空；不能通过普通 JSON 创建／替换接口挂接任意封面 ID。本人、管理员、可浏览该公开歌单的登录账户，或有效获授权且有媒体读取权限的 Key 可读取对应封面。封面随数据库备份保存。

源码更新并启动新程序后，浏览器按 Ctrl+F5 刷新页面。所有管理资源仍内嵌在单个服务器程序中，分发程序时无需额外拷贝网页文件。

全局曲库不再插入顶部批量操作栏或显示每行操作按钮：勾选曲目后右键批量处理，Shift+F10 和手机长按同样可用；右键不会改变列表位置。标题仍可打开详情。

上传显示浏览器实际发送字节、百分比、平均速率；发送完成后独立显示等待服务器校验，不为校验编造百分比。上传不再等待管理请求队列里的封面下载。服务端区分接收、排队、暂存写入、音频流探测、标签／哈希和保存耗时；只探测一次并复用技术参数。自动匹配到新的附件时仅上传封面，不重传音频。暂存复制／探测最多两个并行任务，不占用全局暂存锁，过期清理跳过仍在写入的文件。

系统日志默认位于数据库旁的 `logs/activity.jsonl`，单文件 4 MiB，最多五个文件，目录 0700／文件 0600（Unix）；服务重启恢复最近记录，页面最多显示 500 条，可筛选并加载更早数据。日志接口 `GET /api/v2/admin/logs` 支持 level、category、q、before／after、limit（1–200）；常驻查询窗口最近 2000 条。日志只接受预定义事件及受限结构字段，路径去除标识符和查询参数，不记录密码、Key、Cookie、请求正文或原始错误全文。磁盘写入失败时内存记录保持有界并在页面提示；日志不能替代数据库操作审计。

本版采用账号密码登录和账号所属的播放器 Key，自动保留已知 schema 7 原库并事务迁移为 schema 8。schema 1–6、无版本库、旧启动管理员 Key、匿名管理员模式、JSON 文件及 `/api/v1` 不支持自动转换；程序拒绝后保持原库，应另行备份和制定转换方案，不能通过清库或修改版本标记代替迁移。默认数据库固定为 `build/data/library.sqlite`，不会回退打开 `library-v4.sqlite`。首次安装的管理员密码由用户在网页设置，已有安装继续使用原密码。

## 个人中心

0.20.2 提供注册／邮箱验证：旧账户（含管理员）默认需要验证邮箱后上传；管理员创建成员时填写登录名、配额，可选择是否要求邮箱验证。个人中心提供绑定／更换邮箱及本人容量，后台“邮件服务”“注册与账户”控制 SMTP 和默认关闭的自助注册；注册默认配额只影响之后成功注册的账户。schema 7 及已有资源保留，已有只读播放器 Key 不因邮箱未验证失效。首次启用、邮件凭据和备份恢复步骤见 [使用说明](../Docs/注册与邮件服务使用说明.md)，验收见 [开发计划](../Docs/注册邮箱验证与账户配额开发计划.md)。

从右上角账户菜单进入个人中心，或直接访问 `/#/account/profile`、`/#/account/security`、`/#/account/sessions`。普通用户与管理员均只能在此修改本人的昵称和密码；管理其他账户继续使用账户管理。首次使用临时密码登录时，仍须先完成强制改密。

登录名唯一且只读，用于登录和指定账户分享；昵称用于展示，默认等于登录名，去首尾空白后为 1–128 个 Unicode 字符，允许中文和重名。账户管理及分享邀请显示昵称和 `@登录名`，实际归属与授权始终使用 UUID。昵称保存使用用户版本校验，过期时保留输入并提示重新读取，不覆盖另一标签页或管理员的修改。

修改密码须提供当前密码和两次新密码；新密码至少 12 个字符、最多 1024 个 UTF-8 字节，并与当前密码不同。成功后退出全部浏览器登录，保留播放器 Key。登录管理显示本人有效登录的创建、最近活动及到期时间，当前登录置顶；可退出指定登录或其他全部登录，不影响其他账户和播放器 Key。当前不展示未采集的设备／IP 信息。

本人资料接口 `PATCH /api/v2/auth/me` 只接受 `{ "display_name": "昵称" }`，必需 `If-Match` 为当前用户版本；退出其他登录为 `POST /api/v2/auth/sessions/revoke-others`，返回 `{ "revoked": 数量 }`。两者均只允许账户会话及有效 CSRF，播放器 Key 不可调用。复用现有 users／sessions 表，无需 schema 变更。详情与验收记录见 [个人中心计划](../Docs/个人中心与账户资料开发计划.md)。

## 公开与订阅

新歌单默认私有。在编辑页修改可见性，与名称、简介及封面一起点击保存应用。公开目录仅面向本平台已登录账户，不提供匿名访问。目录按发布时间分页，每页 30 项，搜索支持歌单和作者；网页通过 SSE 接收变化通知，再读取当前页面的增量，正常联网时以 1–3 秒更新为目标。普通目录接口保留专用修订号与 ETag，支持手动刷新。

公开详情地址为 `/#/public/playlists/<UUID>`，复制链接后对方登录仍回到该详情。点击订阅后出现在“我的歌单 → 我订阅的”，关联原 UUID，作者更新会跟随；订阅不复制歌单，不能编辑源结构。作者个人备注不会公开，订阅者的备注按账户隔离。

转私有或作者停用会保留订阅及已配置 Key 授权，但其效力暂停；恢复公开／启用后原 Key 自动恢复。源删除显示最小失效项，不能读取曲目或私有元数据。取消订阅会清除该订阅及其 Key 授权，重新订阅后需重新勾选授权。管理员接管后强制私有，新所有者决定是否再次公开。

Key 授权分“我创建的歌单／我订阅的歌单／全局曲库”，必须显式勾选。有效权限为所选授权与本人可用歌单的交集；失效订阅不影响其他有效歌单或独立全局曲库授权。已有音频下载不能被收回，离线客户端尚未获知的变化仍以最后成功快照为准。

MusicPlayer2 服务器适配 0.13.0 显示 `[订阅]`／`[分享]`／`[失效]` 和失效原因；在线刷新后失效歌单停止当前队列、移出最近入口并禁用播放与离线保存，恢复权限后刷新可用。缓存字节及关联文件保留，不作为有效权限使用。

新增账户接口（均需登录，写请求需 CSRF）：

| 方法 | `/api/v2` 路径 | 用途 |
| --- | --- | --- |
| GET | `/public/playlists?q=&offset=0&limit=30` | 分页摘要、ETag；limit 为 1–100 |
| GET | `/public/playlists/{id}` | 公开只读详情及曲目 |
| GET | `/subscriptions` | 本人订阅，包括最小失效项 |
| PUT / DELETE | `/subscriptions/{id}` | 幂等订阅／取消 |
| PATCH | `/subscriptions/{id}/tracks/{trackID}` | 本人备注 `{ "note": "…" }`，If-Match 为 subscription_version |
| PUT | `/playlists/{id}/visibility` | visibility 为 private／public／shared，If-Match 为歌单 version |

`editor` 表单增加可选 `visibility`。订阅投影增加 `read_only`、`subscription_status`（active/invalid）、`subscription_reason`（private/owner_disabled/deleted/share_revoked）、`subscription_version` 及 `source_owner_name`。同步保留失效项，权限变化触发 reset；客户端不能把失效空成员当成正常空歌单重新启用。

## 指定账户只读分享

所有者在编辑页将可见性设为“仅分享”，保存后从歌单详情打开“分享设置”，输入对方完整账户名。只允许邀请已存在且启用的账户，不提供普通用户账户列表或前缀搜索。每个歌单最多 100 条邀请，列表分页。

对方在“我的歌单 → 分享邀请”接受或拒绝。接受与建立订阅事务提交，不自动勾选 Key。分享源内容只读，作者与接收者的个人备注仍隔离。邀请链接 `/#/invitations/<邀请UUID>` 保留登录目标，但仅目标账户可读、可接受，转发不会授予别人访问。

邀请状态为 pending／accepted／declined／revoked。待处理不自动过期，所有者可撤回；撤回暂停这条分享授权和已配置 Key，保留最小失效项。再次邀请须显式操作并检查邀请版本，接收者再次接受后才恢复；拒绝不能被旧的接受请求覆盖。转私有或作者停用暂时暂停，恢复仅分享／启用后已接受授权可恢复；管理员接管强制私有并撤销旧邀请，必须由新所有者重新邀请。

取消订阅清除个人备注及对应 Key 授权，已接受邀请仍保留，可从邀请页重新订阅并再次勾选 Key。源删除清理邀请，已有订阅保留最小 deleted 项。公开与其他独立授权照常判断，不将撤回定向分享解释成撤回已有全局曲库或其他歌单权限。

以下接口仅账户会话可用，写请求需 CSRF，返回 no-store；完整接口和错误约定见第二期计划：

| 方法 | `/api/v2` 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/playlists/{id}/invitations` | 所有者分页列表／完整 username 邀请；创建 If-Match 为歌单版本 |
| DELETE | `/playlists/{id}/invitations/{inviteID}` | 所有者撤回，If-Match 为邀请版本 |
| POST | `/playlists/{id}/invitations/{inviteID}/resend` | 所有者再次邀请，If-Match 为邀请版本 |
| GET | `/invitations`、`/invitations/{inviteID}` | 本人收到的分页邀请及单条链接详情 |
| POST | `/invitations/{inviteID}/accept` 或 `/decline` | 目标账户接受／拒绝，If-Match 为邀请版本 |

分页参数 offset／limit 默认 0／30，limit 最大 100。缺版本为 428，旧版本／状态冲突为 409，无权访问为 404；不可邀请的账户统一 400。仅分享不会进入公开目录，分享角色不允许转授、修改源结构或管理服务器。

## 网页社区实时刷新

公开目录及详情、本人订阅及详情、收到的邀请、作者打开的分享设置自动跟随变更，邀请页签显示待处理数量。每个可见标签页使用一条 SSE 连接，只通知本账户当前视图发生的变化；网页合并通知后应用变化项、移除项和新顺序，保留无变化的目录卡片、滚动位置、搜索及分享输入。隐藏标签页停连并暂停检查，重新可见或恢复联网后补取；同时每 60 秒补查一次，连接失败或浏览器不支持 EventSource 时也可使用补查。播放器仍按每小时刷新，不使用网页 SSE。

| 方法 | `/api/v2` 路径 | 用途 |
| --- | --- | --- |
| GET | `/community/events?view=<JSON>` | 同源会话 SSE；ready／change 触发补取，expired 退出，reconnect 重连 |
| POST | `/community/sync` | 带 CSRF 的 `{ "cursor": "", "view": { "catalog": true, "offset": 0 } }`，返回游标与视图差异 |

`view` 可指定 catalog／query／offset、subscriptions／subscription_detail、invitations／invitation_id／invitation_offset、owner_playlist／owner_offset 或 public_detail；所有 ID 按当前用户权限过滤。响应 `sections` 中每段含 changed／removed／order／meta，reset 表示重建基线；没有变化时为空 sections。接口只接受账户会话，播放器 Key 不可调用，不更新最近登录活动。

服务端在事务提交成功后唤醒观察者，合并 150ms 内的连续变化；通知只包含信号，数据仍由接口鉴权。15 秒心跳复核会话，每账户最多 8、全站最多 128 条连接，单次发送最多等待 5 秒。Nginx 模板已配置 `proxy_buffering off` 和 300 秒读取超时，部署时需保留这些配置。

增量比较当前状态与服务端短期指纹基线，不提供历史事件回放。游标绑定账户、会话、认证版本与视图，有效 5 分钟、全站最多 64 条；过期、淘汰或重启时返回 reset，单段超过 5000 项后以该段重置控制基线内存。数据库仍是权威数据，不增加 schema 或持久化事件表。实现及验收见 [实时刷新计划](../Docs/网页社区实时增量刷新开发计划.md)。

## 启动

Windows 使用两个批处理脚本：`build.bat` 执行测试、`go vet` 和编译，固定生成 `build/musicserver.exe`，成功后明确输出 `BUILD SUCCEEDED` 和程序路径；失败输出 `BUILD FAILED` 并返回非零状态。`start.bat` 固定启动该程序，首次启动引导设置管理员密码。从其他目录调用也可；源码更新后先停服再编译。

两个 BAT 在正常结束或出错后默认暂停，按任意键再关闭，避免双击时错误信息一闪而过；暂停后仍返回原退出码。如果提示数据库已占用，说明已有实例正在使用该数据库，请使用现有服务或先停服再启动。自动化调用可设置环境变量 `MUSIC_SERVER_NO_PAUSE=1` 跳过暂停；PowerShell 下可使用 `$env:MUSIC_SERVER_NO_PAUSE='1'`，CMD 下使用 `set MUSIC_SERVER_NO_PAUSE=1`。

```bat
cd server
call build.bat
call start.bat
```

首次启动即提供网页初始化，默认账号名为 `admin`，密码在网页输入并确认，至少 12 个字符、最多 1024 字节；不设置默认密码。初始化页需要 `build/data/setup-token` 中的一次性授权码，防止其他访问者抢先创建管理员。也可使用 `/#setup=<授权码>` 一次性链接，网页读取后立即清除地址栏中的授权码；不要转发或记录该链接。初始化完成后删除授权文件，入口关闭，后台扫描自动开始。未完成时重启保留授权，已有管理员时不会重新开放。CLI `build\musicserver.exe admin init` 保留用于提前初始化，`--data` 和 `--username` 均可省略；离线重置仍需终端。自定义用户名为 3–64 个 ASCII 字母、数字、点、短横线或下划线，首字符为字母或数字，忽略大小写。云端首次设置通过 SSH 隧道或 HTTPS 访问，不通过聊天传递密码。

程序默认监听 `0.0.0.0:8080`，支持局域网访问。媒体库为 **musicserver.exe 所在目录及其子目录，即 build/**，数据库为 `build/data/library.sqlite`，无需显式传参。音频可直接放在程序旁，建议放入 `build/media/`。数据库目录、`.staging` 和 `.server-archive` 不参与媒体扫描。上传音频保存在 `build/uploads`，备份和更新暂存在 `build/data` 下。源码目录中的音频不会被默认扫描。

```text
server/
  cmd/ internal/ scripts/ tests/ deploy/   源码、脚本和测试
  build.bat build.ps1 start.bat            固定构建与启动入口
  package-release.ps1                     可选发布打包入口
  build/                                  Git 整体忽略
    musicserver.exe                       Windows amd64 固定产物
    musicserver                           Linux amd64 交叉编译产物（可选）
    data/ media/ uploads/ .staging/        运行数据，按需创建
    packages/                             发布压缩包（可选）
```

每次编译更新同一位置、同一名称的程序，保留运行数据，不生成带日期或版本后缀的可执行文件；不要将整个 `build/` 作为临时编译缓存自动清空。Git 只管理源码、脚本、测试和文档。构建嵌入 Go 的 VCS 信息，启动日志和 `/api/v2/health` 返回 `commit` 和 `modified`，用于辨认源码提交及构建时是否存在未提交修改；不在 Git 仓库内编译时提交号为 `unknown`。

当前处于开发阶段，数据仅作测试，后续升级不提供旧数据格式兼容或迁移。需要重置时停服后删除 `build/data/`，下次启动重新设置管理员账号；媒体会重新扫描，但原 UUID、歌单和人工修改不保留。日常编译不会自动执行重置。

默认路径和显式传入的相对路径都以 **程序所在目录** 为基准，不受终端当前目录影响。`start.bat` 支持全部可选参数，例如 `-media-root "D:\Music"`、`-data` 和 `-no-scan`；只有使用自定义数据库时，初始化/重置才需要传入相同的 `--data`。按 Ctrl+C 停止服务。

`build.bat` 自动查找现有 Go 安装，也可传入 `-GoRoot "C:\Program Files\Go"`。Windows 固定为 amd64；`build.bat -Target linux` 将 Linux amd64 程序写入同一 `build/` 目录，名称固定为 `musicserver`。依赖 ffprobe 的上传校验仍要求安装 ffprobe，见下文；远程部署仍需 HTTPS 和外部地址配置，本机默认使用无需这些参数。

也可直接使用 Go 和 PowerShell 启动：

```powershell
cd server
go build -trimpath -buildvcs=auto -o ./build/musicserver.exe ./cmd/musicserver
.\build\musicserver.exe
```

本机浏览器打开 `http://127.0.0.1:8080/`；同一局域网的其他设备打开 `http://服务器的局域网IP:8080/`，输入账号密码登录。`0.0.0.0` 是监听地址，访问时使用实际 IP。管理员在“账户管理”创建成员，自定义登录名和显示名；每个账户生成独立临时密码，仅成功创建或重置时显示一次，关闭弹窗即清空。请安全交给本人。成员首次登录必须修改临时密码，完成前不能浏览曲库、上传或使用 Key。初次设置的管理员密码无需重复修改。无交互后台环境也能直接提供网页初始化，不创建默认密码。

成员可使用全局曲库、我的歌单、我的上传、本人 Key/统计和个人改密。管理员额外使用账户管理、资源接管及服务器维护。管理员重置他人密码会撤销会话并重新要求改密，可显式选择同时删除该账户的全部 Key、授权和统计；重置本人请使用顶部“修改密码”或停服后的本机恢复命令。

登录名保留创建时输入的 ASCII 字母大小写，去除首尾空白；登录、重名检查、密码重置和邀请查找不区分大小写。例如 `Alice` 与 `alice` 不能创建为两个账户，登录后显示创建时的 `Alice`。旧版已转成小写的账户保持现有拼写，无法自动推断最初输入。

停用账户会立即阻止登录和 Key 使用、撤销会话，但保留原 Key、授权、到期时间和累计统计。重新启用后，未主动删除、未过期且满足当前权限/改密要求的同一 Key 恢复使用，统计继续累计；旧浏览器会话不会恢复。账户停用不下架全局曲目，也不自动转移资源。

删除账户：管理员先停用该账户，在其资源页接管全部管理曲目及私人歌单，然后从用户列表或账户详情点击“删除账户”并确认。尚有管理资源、账户已重新启用或版本变化时拒绝删除；不能删除当前登录管理员。成功后账户从正常列表消失，清除密码凭据、会话、Key、授权、统计、订阅和邀请，不能重新启用或重置密码。UUID、原登录名／昵称、原始上传者及审计记录保留，登录名继续占用，已接管资源和媒体文件不删除。删除时间保存于现有 meta 表的 `deleted_user/<UUID>`，保持 schema 7；剩余上传暂存按原到期机制回收，不能再提交。固定扫描归属若指向该账户，会原子转给当前管理员。详见 [账户删除计划](../Docs/账户删除与Key直接删除开发计划.md)。

密码采用 Argon2id，独立 16 字节盐、19 MiB 内存、2 次迭代、并行度 1；数据库只保存密码哈希和会话令牌哈希。Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 部署启用 Secure。浏览器写请求验证 Origin/Referer 和 `X-CSRF-Token`；登录验证来源，失败提示统一，账号每分钟最多 5 次尝试、IP 每分钟 30 次，最多 2 个并发密码哈希任务。成功登录重置该账号的尝试计数。

会话空闲 2 小时、绝对 7 天过期；后台轮询不续期，真实用户活动限频续期。刷新页面保持登录，服务重启撤销全部旧会话，播放器 Key 不受重启影响。改密撤销全部浏览器会话，普通改密不删除播放器 Key；页面可显式删除我的全部 Key。

绑定通配地址或私网 IP 且未设置 `public-url` 时启用局域网 HTTP：只接受本机、私网及链路本地来源，并要求 Host 为本机名 localhost 或本机/私网 IP；不信任转发头来绕过限制。保留账号鉴权、同源校验、CSRF、HttpOnly 与 SameSite=Strict Cookie。HTTP 无传输加密，仅用于可信局域网。若仅本机使用，可传入 `-addr 127.0.0.1:8080`。

局域网 HTTP 页面支持新建歌单、上传和复制完整 Key。自动复制不可用时，页面会选中完整 Key 并提示手动复制，不会显示复制成功。没有私人歌单或没有勾选任何授权时，Key 仍可通过认证并返回空列表；要在播放器中看到全局曲库，需要显式授权系统 library。401 表示密钥无效、已过期/撤销或账户不可用，与歌单为空无关。若此前复制失败且一次性弹窗已关闭，请新建或轮换 Key，再将完整值填入播放器并应用设置；列表中的 Key ID 不能用于认证。

公网部署继续通过 HTTPS 反向代理，并配置 `-public-url https://music.example.com` 或 `MUSIC_SERVER_PUBLIC_URL`，固定外部来源并使用 Secure Cookie。显式绑定公网 IP 不允许无 HTTPS 配置启动。后端应绑定回环或受限内部接口，防火墙禁止公网直接访问明文后端端口；`public-url` 固定浏览器来源，不等于关闭明文监听。只有固定HTTPS来源模式下的回环代理传入单值有效 `X-Forwarded-For` 才用于登录／注册／邮件限流；官方Nginx模板覆盖该头为直接来源，其他连接不信任转发头。

忘记密码时停服后在终端执行（可选 `--revoke-keys` 同时撤销该账号播放器凭证）：

```bat
build\musicserver.exe admin reset-password
```

服务和本机管理命令共用 OS 文件锁，服务运行时拒绝 CLI 初始化/重置同一库，进程退出时自动释放锁。CLI 初始化和重置要求真实交互终端，不接受密码参数或重定向密码输入；网页首次初始化不受此终端要求限制。

启动自动开始后台快速扫描，`-no-scan` 可关闭。Ctrl+C 或 SIGTERM 会取消扫描、停止更新任务并尝试等待 HTTP 请求退出。数据库和媒体目录应放在持久存储中，一个数据库只运行一个服务进程。

上传要求安装 ffprobe：在设置中指定 `ffprobe_path`，或配置 `MUSIC_SERVER_FFPROBE`，或将 ffprobe 加入 PATH。没有可用探测工具时上传校验失败；本地目录扫描仍可使用有限的 WAV/FLAC/MP3 参数解析。

## 曲目身份与数据

曲目文件位置以媒体库根目录下的相对路径保存。同一数据格式下，停服后将 **整个 build/ 运行目录（含程序、数据库、音频）一起移动**，直接运行其中的程序即可继续使用，UUID、歌单、人工修改和账号保持不变，不需要携带源码。只复制音频到新库可重新扫描导入，但不会带回数据库中的 UUID、歌单等信息。若显式配置了外部绝对路径，该外部目录需要一起保留或重新指定；单独移动/重命名音频按下述哈希匹配规则识别，不保证重复文件的无歧义匹配。

- 曲目 `id` 是首次建库时生成的 UUID v4，与数据库记录一一对应。歌单和人工修改引用 UUID。
- `uploaded_by` 是不可变的原始上传者；`owner_id` 是当前管理者，接管只改变管理者。扫描新曲目归发起扫描的管理员，自动扫描使用初始化时记录的管理员；重扫和移动识别保留归属。原始上传者或管理者停用，不影响其他启用用户播放。
- `path` 是媒体目录下的唯一相对路径，可变化；`content_hash` 是文件 SHA-256，用于完整性校验、上传去重和移动识别，不作为曲目主键。
- 相同路径重扫沿用 UUID。在同一次扫描中，旧路径消失、新路径出现，且哈希仅对应一个旧候选和一个新候选时，认定移动或重命名并沿用 UUID。存在重复内容歧义时创建新记录，旧记录保留为缺失，避免错误合并。
- 文件丢失标记 `missing=true`，保留曲目、歌单顺序、成员备注及人工覆盖；原路径文件恢复后可通过扫描清除缺失状态。媒体接口对不可用文件返回错误。
- 移除曲目标记 `removed=true`，保留原文件和用户歌单关系；扫描不会自动恢复被移除的曲目。管理页概览的已移除列表可显式恢复，恢复后 UUID 不变。常规曲目列表和同步不展示已移除曲目；用户歌单管理接口保留成员 ID，便于恢复及排序。
- 直接在原路径替换文件内容仍视为该记录的文件更新。若需表示新的独立曲目，使用新的文件路径；系统不依据音频相似度猜测关联。

SQLite 为权威数据源。写入针对相关记录，通过同一事务提交业务数据、版本、增量日志与审计；不再维护常驻的全库内存快照，也不在单项修改时清空并重写所有表。封面按内容哈希独立保存，原音频标签不会因管理页编辑而被重写。

## 扫描与上传

`POST /api/v2/admin/scan` 返回 `202`，使用查询参数 `?full=true` 请求全量重算，默认快速扫描。`GET /api/v2/admin/scan/status` 查询状态，`POST /api/v2/admin/scan/cancel` 取消；同一时间只运行一个扫描。管理页提供快速/完整扫描、进度和取消入口。

快速扫描比较文件大小、修改时间和同目录歌词/封面状态，未变化的文件跳过读取和哈希；完整扫描重新读取全部候选。若外部工具修改内容却刻意保留大小和时间，需要完整扫描。`processed` 为实际检查候选数，`changed` 为成功提交的曲目变化数；单文件错误最多保留 100 条。

文件解析、哈希和探测在数据库写事务之外进行，最后一次事务应用结果，重新读取人工覆盖和当前版本，保留并发编辑。单文件失败保留原记录并报告错误；遍历目录失败、取消或事务失败不提交扫描变更。成功扫描没有变化时不增加库修订号。扫描结果提交仍为单事务，大库提交阶段可能短暂阻塞其他数据库请求；此版本使用单连接和 DELETE journal。

支持音频标签、同名 `.lrc`/`.elrc`/`.txt` 外置歌词、内嵌/同名/专辑/目录封面。歌词支持 UTF-8/BOM、带 BOM 的 UTF-16 和 GB18030。封面和歌词匹配规则见 `../Docs/外置歌词与封面处理.md`。不调用外部歌词平台。

管理页支持多文件、文件夹和拖放目录。MP3 可在浏览器本地预览，点击上传校验后才发送文件、暂存并返回 `validation=audio_stream_verified`，确认后入库。ffprobe 验证至少存在可识别音频流，**不代表完整解码或全文件无损坏**。暂存有效期 30 分钟，后台每分钟清理；确认时再次检查内容重复，重复上传复用已有可用曲目且不覆盖其元数据。上传文件发布与扫描读取协调，避免扫描半成品。

默认上传限制 512 MiB，可在设置调整至最多 4 GiB；HTTP 限制包含 multipart 开销。元数据请求限制 2 MiB，标签读取预算 32 MiB，单条歌词最多 2 MiB；封面限制 8 MiB、20 MP。浏览器标签解析使用内置 jsmediatags 3.9.7，许可和本地补丁说明见 `internal/music/vendor/`。

## 条件修改

容量与额度入口为“系统设置 → 容量与额度”。显示数据卷／媒体卷可用空间及总量，数据库（含 WAL）、已入库音频、暂存、备份、应用更新缓存的独立分类；同一卷的两项可用空间不要相加。账户按原始上传者、实际存在的音频文件大小统计，包含已下架文件；接管不改变占用，重复上传复用不重复计费。默认不限额（0），管理员可按账户设置，降低额度不会删除文件。账户额度约束新上传确认入库；管理员目录扫描仍可导入文件。系统日志及未知文件不计入音频用量，但卷余量包含它们。

磁盘默认预留 512 MiB，可在该页修改。接收上传时同时检查操作系统临时盘、媒体盘及数据盘；写入、确认及数据库持久化前再次检查，低空间返回 `507 STORAGE_LOW`，额度不足返回 `409 STORAGE_QUOTA`。失败清理本次临时输出，保留已有曲目；额度确认在写事务内执行，防止并发超额。备份提前估算快照和归档所需空间并在压缩写入时复查。恢复要求目标盘剩余空间可容纳解包内容、数据库调整及 512 MiB 余量。外部进程可同时占盘，这些检查不能替代文件系统配额。

安全清理只删除受管版本目录中的旧更新下载包，保留当前、待更新及回退所需版本，不删除已安装程序、回退数据库、媒体、未知文件或系统目录；更新工作中拒绝清理。完整备份在备份页逐份显式删除。容量接口为管理员会话专用：`GET /api/v2/admin/storage`、`PUT /admin/storage/policy`、`PUT /admin/storage/quotas/{userID}`、`POST /admin/storage/cleanup-updates`（后三项前缀同为 `/api/v2`）。策略与额度以 `version` 检测并发冲突，复用现有 settings 表，schema 不变。

曲目和歌单返回 `version`。对已有曲目、歌单及其成员/附件的修改、删除，以及曲目恢复，均提交当前版本：

```http
PATCH /api/v2/tracks/曲目UUID
Cookie: music_session=登录得到的会话令牌
Origin: https://music.example.com
X-CSRF-Token: 登录或auth/me返回的csrf_token
If-Match: "3"
Content-Type: application/json

{"title":"新标题"}
```

缺少有效 `If-Match` 返回 `428 VERSION_REQUIRED`；版本已变化返回 `409 VERSION_CONFLICT`。刷新后由用户重新确认修改，不自动覆盖他人的更改。创建歌单时 ID 已存在返回 `409`。

歌单成员排序同时提交 `track_ids` 和读取时的 `expected_track_ids`；歌单显示排序提交 `order` 和 `expected_order`，以检测并发变化。显示顺序仅作用本人私人歌单；系统 `library` 固定在前并自动维护曲目，不参与个人排序或接管。用户歌单成员备注独立于全局曲目备注，其他成员不能读取私人歌单或猜测其存在性。

全局曲目仅管理者或管理员可修改。成员软删除本人管理的曲目前，事务内检查其他账户的私人歌单引用；停用账户的引用也受保护，系统曲库不计入。存在引用返回 `409 TRACK_IN_USE`，不披露引用者身份或备注；管理员可下架并恢复。下架不删除原文件，歌单保留 UUID、顺序与备注，详情返回最小不可用曲目占位。成员无法通过重复上传恢复已下架内容。

## 增量同步

首次 `GET /api/v2/sync?limit=100` 获取分页快照，以后传入上一页返回的 `cursor`。默认每页 100 项，最多 500 项；按实体或日志条数分页，单条曲目歌词及单个歌单成员列表不会再拆分。

响应包含 `changed_tracks`、`playlists`、`deleted_tracks`、`deleted_playlists`、`cursor`、`has_more`、`full_snapshot`、`reset` 和 `revision`。客户端应：

1. `reset=true` 时清空该服务器的旧缓存；仅新快照的第一页发出 reset。
2. 按 UUID 应用更新和删除，`has_more=true` 时继续请求下一页。`deleted_tracks` 删除的是可用曲目缓存，不能据此删除私人歌单的成员 UUID 或备注；歌单的 `unavailable_track_ids` 表示需要显示占位的成员，恢复后更新占位。
3. 完成所有页后保存最终游标；后续轮询使用游标，不能用 `revision` 替代游标。

游标由 HMAC 签名，绑定账号 UUID、权限版本、会话/Key、角色、scopes、当前可见歌单 ID（含空歌单）和 Key 授权成员集合；有效期 24 小时。会话同步全局曲目及本人的私人歌单，管理员查阅他人资源使用管理接口，不混入普通同步。过期、授权或可见范围变化会重新发快照并返回 reset，客户端必须清理失去权限的数据。同步事务内复核账户和 Key，防止已认证请求跨接管读取他人新内容。快照分页期间库发生变化返回 `409 SYNC_RESTART`，丢弃中间结果并不带游标重试。

变更日志持久保留最近 10,000 条事件，游标超出窗口自动退回快照。增量页读取实体当前状态，在连续变化期间以完成后续页达到最终一致；客户端须完成分页。管理页的普通曲目/歌单列表仍是完整列表，大库客户端应使用分页同步。压缩可在反向代理启用。

## 权限与并发

浏览器使用账号会话，`/admin/` 接口只接受管理员会话；成员可管理本人的歌单、Key、暂存和管理中的曲目。播放器认证头使用 `X-API-Key` 或 `Authorization: Bearer ...`，Key 归属账号、只保存密钥哈希，创建/轮换时仅返回一次完整密钥。Key 只能配置 `library:read`、`media:read`，默认无歌单授权；显式空 scopes 禁用全部能力。Key 只能显式授权本人私人歌单或系统 `library`，成员的全库浏览权限不会自动透传给 Key，管理员的管理访问也不会透传。显式 Key 优先于 Cookie，失败时不回退，也不合并权限。

| Scope | 接口能力 |
| --- | --- |
| `library:read` | 曲目、歌单、同步 |
| `media:read` | 音频、封面 |

`max_concurrency` 为 Key 元数据请求并发数，默认 4，范围 1–64；`max_downloads` 为音频和封面下载并发数，默认 1，范围 1–16。两者独立，下载不会占满元数据限额；超限返回 `429` 和 `Retry-After: 1`。账号会话不受 Key 限额约束。并发计数仅在当前进程有效；设备绑定和心跳租约不在此版本范围内。

管理员“账户管理”按账户分页查阅当前管理/原始上传的曲目、私人歌单及脱敏 Key。停用来源后，可将所选或全部曲目与歌单接管给一个启用账户。请求验证来源、目标及每个资源版本，冲突整体回滚；不转移 Key 或会话，不改变原始上传者，清除被转移私人歌单的旧 Key 授权。原账户重新启用后资源不会自动返还。管理读取、启停、改密重置和接管均记录审计。不提供公开注册或匿名分享；站内公开和邀请链接见前述分享说明。

接管请求示例（从资源查询响应获取当前版本）：

```json
{"target_id":"目标账户UUID","target_version":2,"all":false,"tracks":[{"id":"曲目UUID","version":3}],"playlists":[{"id":"歌单ID","version":4}]}
```

`If-Match` 使用来源账户版本。`all=true` 时仍需提交来源全部曲目和私人歌单的完整版本清单，服务端校验数量与当前归属，不允许遗漏资源后宣称整账户接管。

调用统计仅按当前仍存在的播放器 API Key 持久记录次数、成功/失败、字节和耗时；账号会话、匿名请求及健康检查不计入。新增 Key 自动显示零调用记录，改名同步显示。主动撤销现直接物理删除 Key、授权、scopes 和统计，页面称为“删除”，不保留可轮换恢复的撤销项；单个、全部删除和管理员重置密码的清除选项遵循同一规则。旧凭证完成中的请求不会重建已删除统计。有效 Key 的历史计数在重启后保留，启动时清理历史会话／匿名统计，并删除旧版本保留的已撤销 Key 及其关联记录；过期但未删除的 Key 仍保留历史统计。审计记录操作人、凭证类型、账号 ID、凭证 ID、动作、实体和时间，密码和令牌不写入审计。审计和备份可能包含私人元数据，应限制文件访问；Windows 权限还需要由部署目录 ACL 控制。

## 备份、恢复和更新

可选 `package-release.ps1` 复用统一构建入口，生成 `build/musicserver.exe`、`build/musicserver`、独立 `build/musicserver-updater` 和 `build/packages/` 的固定名称包。Windows 包包含程序、build.json 与说明；Linux 包另含独立更新器及部署模板，均不包含数据库、媒体、密码或实际运行配置。包名不随版本变化。本地打包不签名，正式签名包由 GitHub Actions 生成。

系统设置 → 备份与恢复可创建完整或仅数据库备份，显示阶段、字节进度，支持取消、下载和删除。完整归档包含一致 SQLite 快照、已入库音频、相关歌词／封面和应用设置，逐文件记录大小及 SHA-256；已缺失文件在清单注明。归档位于数据库旁 `backups/backup-UUID.tar.gz`，不包含程序、暂存、日志、其他备份或未知文件。Nginx、systemd、TLS 私钥、证书及云凭证须独立备份。归档含密码哈希及私人内容，应妥善保管。

自动备份默认关闭，可在网页启用；间隔 1–168 小时，保留 1–30 份。仅自动清理超量的自动归档，手工备份须显式删除；正在下载的归档受保护。失败不覆盖成功备份，至少一小时后重试。

恢复到新的空目录：`musicserver backup restore --file /path/backup-UUID.tar.gz --destination /path/restored`（Windows 使用 `musicserver.exe`）。工具校验路径、类型、大小、摘要、schema 及数据库完整性，拒绝覆盖非空目录。输出 `restored/data/library.sqlite` 和原相对路径媒体；将程序放到 restored 根目录后可按默认路径启动，Linux 须重新配置部署路径和文件权限。恢复保留 UUID、账户、歌单及 Key，撤销旧会话、清除暂存记录、关闭自动备份并重定位媒体根目录。仅数据库备份需另行提供匹配音频。可能恢复旧密码及旧 Key，须核对并按需轮换。schema 1–6 不支持本版恢复，不可直接覆盖运行中的数据库。

默认检查公开仓库 `ShenYunyao1/MusicServer`；`update_repository` 可指定检查来源。启动及每 6 小时只检查正式 Release 的签名元数据，不下载、不安装。Windows 支持检查与手工替换。Ubuntu 配置独立 systemd 更新器后，管理员可以显式选择兼容版本，自动完成验证签名与包哈希、停止服务、最终数据库备份、切换程序和重新启动；健康检查失败会恢复旧程序及数据库。跨 schema 自动安装仅支持签名清单明确声明且独立 root 更新器具备能力的 7→8；其他路径继续拒绝。自动安装固定信任官方仓库与内置公钥，不能通过网页改为任意程序源。详细目录、权限、恢复和发布流程见 [Ubuntu 部署说明](deploy/README.md)。

## 验证

```sh
go test ./...
go vet ./...
go test -race ./...
go build -o ./build/musicserver ./cmd/musicserver
```

Race 检查需要支持的 C 工具链。隔离浏览器回归 `tests/management-ui.cjs` 自建临时媒体、数据库和子进程，不连接现有服务器：

```powershell
$env:MUSIC_SERVER_TEST_BINARY = (Resolve-Path '.\build\musicserver.exe').Path
$env:MUSIC_SERVER_PLAYWRIGHT = 'playwright'
$env:MUSIC_SERVER_TEST_PYTHON = 'python'
node tests/management-ui.cjs
```

安装 Playwright 及其 Chromium、Python 后运行；终端初始化测试在 Windows 需要 pywinpty，其他系统需要 pexpect。`MUSIC_SERVER_PLAYWRIGHT` 也可为模块绝对路径。浏览器回归调用 `multiuser-ui.cjs` 和 `users-ui.cjs`，覆盖管理员和两个成员的首次改密、上传收藏、私人备注、引用保护、下架恢复、Key/统计隔离、启停同密钥恢复和资源接管，以及原有管理流程。Linux 交叉编译不等于已在 Linux 主机实际运行验证。

账户与 Key 删除专项设置 `$env:MUSIC_SERVER_TEST_ACCOUNT_DELETE_ONLY='1'` 后运行 `node tests/management-ui.cjs`，与实时专项开关分开使用；完成后移除环境变量。覆盖删除 Key／全部删除／跨账户隔离、取消确认、停用及重新启用同 Key、账户资源约束、版本冲突、接管后从详情删除、保留歌单和刷新持久化。Go 专项为 `go test ./internal/music -run '^TestAccountDeletion|^TestKeyDeletion' -count=1`，另覆盖原始上传者、schema／外键、清理失败回滚及请求鉴权后操作者被删除的并发交错。创建／管理账户在事务内复核操作者身份，不能利用已开始的请求继续取得临时密码。完整浏览器回归也包含删除模块。

个人中心专项浏览器验收使用相同环境变量运行 `node tests/personal-center-ui.cjs`，仅需 Playwright／Chromium，无需 Python 或音乐样本；测试自行建立本地端口、管理员和测试成员，测试数据及截图在忽略的 `build/personal-center-*` 目录。可选 `MUSIC_SERVER_BROWSER` 指定已安装 Chromium 的程序路径。覆盖昵称保存／持久化／冲突／同名分享、未保存输入、首次改密、单个及批量退出、改密后浏览器失效而 Key 保留、375px 移动布局。Actions 已接入完整管理页、个人中心、实时刷新三项隔离浏览器回归，失败阻止发行；依赖由 `tests/package-lock.json` 固定。
