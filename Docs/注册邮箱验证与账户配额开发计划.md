## 二、账户标识与创建方式

| 字段 | 规则 |
| --- | --- |
| 账户 UUID | 继续由服务器生成，永久关联资源、Key 和溯源；不要求人工填写，列表不必突出展示 |
| 登录名 | 管理员创建或注册时必填，唯一查找继续忽略大小写，保留输入拼写；沿用既有格式规则 |
| 昵称 | 默认等于登录名，由本人在个人中心修改；创建表单不再要求重复输入 |
| 邮箱 | 仅本人及有权限的管理员查看，不出现在歌单作者信息、播放器接口或公共目录 |

管理员创建成员表单包含“登录名”“存储配额”“需要验证邮箱”三个项目。验证选项默认勾选，配额支持不限额及具体 MiB／GiB；不得把未填写误存为不限额。继续生成独立临时密码，仅显示一次，首次登录强制修改。创建账户、指定配额及验证要求应在同一事务完成，失败不遗留半成品。

管理员选择免验证时，完成首次改密后可按指定额度上传；选择需要验证时，指定额度先保留，邮箱验证成功后才允许上传。管理员可在账户详情调整验证要求，所有豁免和恢复要求均写审计记录。普通账户不能修改自己的验证要求，注册请求也不能自行指定豁免或额度。

## 三、旧账户与上传资格

首次启用该功能时，对全部未删除的旧账户初始化 `email_verification_required=true`，包括管理员账户。初始化只执行一次，并持久化完成标记，后续重启或升级不得覆盖管理员明确设置的豁免。

旧账户原有额度、已用容量、UUID、曲目、歌单、订阅、Key 和归属保留；不重新套用新注册默认额度，也不因未验证而删除文件。停用账户重新启用后仍按其邮箱验证要求判断上传资格。

上传资格统一为：账户已启用且未删除、已完成首次改密，并且“免验证”或“已绑定有效的已验证邮箱”。额度不足和磁盘空间不足仍独立检查。当前额度 `0` 代表不限额，**不得以 `0` 代表尚未获得上传资格**，也不得通过把原配额改为零来限制旧账户。

| 账户情况 | 上传行为 |
| --- | --- |
| 旧账户，默认要求验证，尚未验证邮箱 | 禁止新上传，保留原额度；验证后继续按原额度使用 |
| 管理员创建，勾选需要验证 | 验证前禁止上传；验证后使用创建时指定额度 |
| 管理员创建，明确免验证 | 完成首次改密后，按指定额度上传 |
| 自助注册 | 强制要求验证；验证后激活注册时锁定的默认额度 |
| 停用、已删除或仍须首次改密 | 邮箱验证不能绕过原有账户限制 |

未验证账户仍可登录、进入个人中心绑定邮箱、浏览／播放现有曲库和使用已有歌单及只读 Key。管理员仍可进入用户管理和邮件设置，避免配置邮件服务时被锁在后台之外；豁免上传必须是明确的账户设置，不能隐式依赖管理员角色。

统一上传检查覆盖旧 multipart 上传、创建续传、追加块、finish 校验、暂存附件修改和确认入库；读取请求体后、写检查点／发布曲目前再次复核。旧会话和直接 API 请求不能绕过。资格不足时不新建暂存文件；已有任务不能继续写入或入库，但允许本人查看状态和取消，不自动删除已确认片段，按现有到期策略清理。

邮箱未配置或投递失败时，不自动放宽验证要求。普通页面明确提示联系管理员；管理员可以先完成邮件配置，或显式为指定账户设置豁免。管理员目录扫描继续作为独立管理操作，不冒充个人上传。

## 四、注册与默认配额

自助注册默认关闭；管理员先配置并测试邮件服务、明确设置新注册默认额度，再启用注册。可单独关闭注册，同时继续允许已有账户绑定／更换邮箱。关闭注册不删除已经创建的账户或使其验证码失效。

流程为“登录名和密码注册 → 登录 → 个人中心输入邮箱并验证 → 激活上传资格”。密码沿用现有安全存储及长度要求，用户自行设置的密码不再要求立即重复修改；昵称默认同登录名。

注册事务保存当时的默认额度及策略版本，不在每次读取账户或验证邮箱时动态查最新默认值。注册时的默认额度不可由前端提交；新注册默认值的变更只影响变更后成功注册的账户。

例如：甲在默认 1 GiB 时注册但未验证，管理员改为 2 GiB 后乙注册；甲后来验证仍为 1 GiB，乙为 2 GiB。原有账户不受该默认值变化影响。默认额度数值由管理员明确配置，本计划不预设无限额。

验证码消费、邮箱绑定和首次激活资格须原子且可重复请求：重复验证、重发、更换邮箱不叠加额度；管理员已调整的额度不能被默认额度覆盖。额度来源区分旧有／管理员指定／注册默认快照，便于解释和审计。

## 五、邮件与验证码

采用支持 TLS 的通用 SMTP 适配，不在云主机自建投递服务器。服务商、发信地址及必要域名由实际部署时配置，不在源码绑定个人邮箱。Resend 等服务可以接入 SMTP，但需要自有发信域名验证，参考 [SMTP 官方说明](https://resend.com/docs/send-with-smtp) 和 [发信域名要求](https://resend.com/docs/dashboard/domains/introduction)。网站目前使用公网 IP，不代表已拥有发信域名。

“系统设置 → 邮件服务”提供主机、端口、TLS 方式、发信地址、凭据配置状态及测试邮件；“系统设置 → 注册与账户”提供注册开关和新注册默认额度。非秘密配置与策略持久化；凭据仅保存在服务端受限权限的秘密配置中，不回显到前端、不进 Git、不进日志、不随普通备份导出。恢复备份后可重新配置秘密，不能因缺少邮件凭据而自动豁免验证。

验证码规则：使用安全随机生成的六位数字，10 分钟有效，重发间隔 60 秒，单个挑战最多尝试 5 次；同时设置账户、目标邮箱、可信客户端 IP 和全站发送上限。反向代理来源按可信代理规则识别，不能直接信任任意转发头。数据库仅保存带服务端密钥的摘要，绑定账户、目标邮箱、用途和有效期；只消费一次，重发使旧挑战失效。登录密码、临时密码、验证码及完整邮件内容不写日志。

SMTP 发送使用持久任务及有界重试，记录排队／已提交邮件服务／失败状态；提交成功不声称收件人一定收到。失败给出可理解的重试提示，过期任务不再投递；并发重试使用幂等标识，限制重复发送。系统日志显示脱敏邮箱、任务编号和失败原因，邮件验证／豁免／额度变更另写操作审计。

同一已验证邮箱不得同时绑定多个有效账户；不擅自删除加号后缀、合并不同邮箱地址或把整段地址一律小写，明确邮箱规范化及唯一性规则。更换邮箱需验证当前密码及新邮箱，新邮箱验证完成前保留旧绑定；成功后原子替换且不重新授予额度。普通用户不提供直接解绑后获得新额度的入口。软删除账户保留邮箱占用记录；管理员可以显式释放并审计，释放后才可被新账户绑定，不改写旧账户的溯源。不把邮箱验证宣传为能阻止所有多账户行为。

## 八、验收标准与命令

本地按阶段运行针对性 Go 和浏览器专项；完整 Go／vet、Linux race、网页及两端原生兼容交 Actions，推送仍需后续明确授权。文档阶段只检查本计划、差异及工作区，不运行无关全套测试。

预计专项命令：

```text
cd server
go test ./internal/music -run 'TestRegistration|TestEmail|TestMail|TestUploadEmailPolicy' -count=1 -timeout 120s
go test ./internal/music -run 'TestStorage|TestResumable|TestBackup' -count=1 -timeout 180s
go vet ./internal/music
node tests/management-ui.cjs
```

新增测试名称以实现为准；目标回归应覆盖以下事实后，才能勾选对应阶段：

- 旧账户和已有登录会话都会受到上传验证限制，原有配额、资源和只读访问保持；旧管理员仍可配置邮件。
- 管理员创建时的验证选项和额度真正持久化，免验证不是前端按钮假象；自助注册不能伪造豁免。
- 策略变更只影响随后注册的账户，延迟验证仍用注册快照；旧账户验证不领取新注册额度。
- 重复验证和并发验证最多消费一次；管理员并发改额度不被覆盖；错误、重放、到期、跨账户验证码均失败。
- 未验证不能创建／追加续传或确认旧暂存；传输期间资格撤销不能继续推进；取消和状态读取仍可用。
- 发码失败、延迟、服务重启、账户切换、浏览器刷新和限流都给出正确状态；凭据与验证码不出现在日志、API 或普通备份中。
- 所有相关页面在桌面和手机可用，既有登录名大小写、临时密码、启停、删除／接管、Key、订阅及邀请流程仍通过。

## 九、外部依赖与当前状态

实际邮件联调需要管理员提供可用 SMTP 服务及发信身份；域名型服务还需完成发信域名验证。凭据通过受限配置输入，不在聊天或仓库明文记录。开发自动化使用隔离假邮件服务，不给真实用户发送测试邮件。

当前仅 P00 完成，其余均未实施、未验收；本计划不代表已授权发布、发送真实邮件或连接云端部署。
