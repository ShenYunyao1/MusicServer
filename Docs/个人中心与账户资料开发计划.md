# 个人中心与账户资料开发计划

日期：2026-10-24。状态：P01–P06 已完成，随 0.17.0 推送并发布，Actions 与正式资产核验通过；云端尚未更新。开发、提交及发布遵循 [开发提交与版本发布流程](开发提交与版本发布流程.md)。

## 一、目标与范围

为所有已启用且完成首次改密的账户提供仅本人可见的个人中心，包括基本资料、修改密码和登录管理。管理员也使用同一个人中心管理自己的资料；管理其他账户仍使用现有用户管理页面。

保留登录名与显示名两个字段，将面向用户的“显示名”统一称为“昵称”。不改变账户 UUID、资源归属、Key 授权或分享关系。

本期不增加头像上传、邮箱／手机号绑定、自助注册、公开个人主页、登录名修改、账户自助删除或角色修改。默认头像使用昵称首字，无有效字符时使用通用账户图标。头像图片上传及裁剪留待后续。

## 二、现状核对

- `accounts.go` 的用户模型已有 UUID、登录名、显示名、角色、启用状态、版本和注册时间；创建账户时显示名为空会默认使用登录名。
- `users.go` 已支持管理员修改显示名，并对公开／定向分享歌单产生必要的目录与同步变化；尚无普通用户修改本人资料的接口。
- `account.js` 已通过右上角菜单提供改密与会话弹窗；`auth_http.go` 已有本人身份、改密、会话列表及单会话退出接口。
- 现有普通用户改密验证当前密码，成功后撤销全部浏览器会话，保留播放器 Key。首次强制改密仍是独立的前置流程。
- 会话列表已有创建、最近活动、到期时间和当前会话标记；尚无可靠的设备名称、浏览器或 IP 展示数据，本期不虚构这些信息。

## 三、产品规则

### 账户标识

| 字段 | 规则与展示 |
| --- | --- |
| UUID | 永久主键，用于资源与授权关联，个人中心不必展示 |
| 登录名 | 唯一、忽略大小写，沿用现有 3–64 个 ASCII 字母／数字／点／短横线／下划线规则；只读 |
| 昵称 | 可自行修改、允许重名和中文，默认等于登录名；沿用当前非空、去首尾空白、最多 128 个 Unicode 字符的规则，前后端一致校验 |

账户创建时昵称为可选项，不要求管理员重复输入登录名。昵称相同不合并用户，不改变任何归属。

普通歌单作者及账户入口以昵称为主。指定账户分享的查询／确认和用户管理中显示“昵称（@登录名）”，按唯一登录名定位账户；不得按昵称模糊命中后直接发送邀请。

### 个人资料

- 个人中心仅修改当前登录账户的昵称；登录名、角色、注册时间只读。
- 保存昵称后立即更新当前页面、右上角账户入口及本地已载入的相关作者名称；其他页面重新获取数据时显示新昵称。
- 公开目录及订阅／指定分享的作者名称通过现有目录版本与同步机制更新；不要求其他客户端立即轮询，不改变其刷新策略。
- 昵称更新不撤销网页登录会话或 Key，不修改任何资源所有者 UUID。
- 资料与密码各自使用独立表单和保存按钮；保存成功显示自动消失的消息，不要求点击确定。失败保留输入并显示字段错误。

### 修改密码

- 使用当前密码、新密码、确认新密码三个输入项，提供显示／隐藏密码功能。
- 沿用当前密码策略：至少 12 个字符，最多 1024 个 UTF-8 字节；新密码不得与当前密码相同。前端确认两次输入一致，后端执行权威校验，不额外强制大小写／符号组合。
- 保存前说明：“修改密码后需要重新登录，播放器连接不受影响。”
- 成功后撤销当前及其他全部浏览器登录状态，清空密码输入和受保护页面状态，返回登录页显示成功提示；默认保留原有 API Key。
- 原有首次登录强制改密流程继续生效；不得因为加入个人中心而允许尚未完成首次改密的账户浏览资料页面或访问其他业务功能。

### 登录管理

- 列出本人的有效登录，展示当前登录标记、创建时间、最近活动和到期时间；当前登录优先显示。
- 支持退出指定登录、退出当前登录和“退出其他所有登录”。批量退出保留当前登录，且不修改播放器 Key。
- 退出其他登录前明确确认操作范围；成功后刷新列表，已退出的浏览器在后续请求时失效。
- 未记录的设备、浏览器、IP 信息暂不展示；后续若采集，应独立定义保存范围与保留期限。

## 四、页面布局与交互

- 从右上角账户菜单进入 `#/account/profile`，入口名称为“个人中心”；退出登录保持为菜单中的独立操作。
- 页面使用现有布局，左上角统一返回入口，返回上一有效站内页面；直接打开个人中心时回到全局曲库。不重复显示相同页面标题。
- 使用“基本资料／账户安全／登录管理”页签，对应 `#/account/profile`、`#/account/security`、`#/account/sessions`，支持刷新及直接访问。
- 基本资料展示昵称首字头像、昵称表单、只读账户信息，并提供跳转现有播放器接入页面的快捷入口；不复制 Key 管理功能。
- 原“修改密码”“登录会话”菜单入口改为跳转对应页签，避免同时维护两套表单；首次强制改密入口不受此调整影响。
- 桌面采用内容宽度受控的表单卡片；移动端单列展示，不产生水平滚动。输入标签、错误提示、焦点与键盘操作保持可用。
- 保存／退出请求进行时禁用对应按钮，防止重复提交；有未保存输入时离开当前表单提醒，取消离开后保留输入。

## 五、接口与存储设计

| 接口 | 处理范围 |
| --- | --- |
| `GET /api/v2/auth/me` | 复用当前身份与用户版本，用于个人资料展示和表单初始化 |
| `PATCH /api/v2/auth/me`（新增） | 仅接受 `display_name`，目标 UUID 从当前会话获取；返回更新后的本人资料 |
| `PUT /api/v2/auth/password` | 复用当前改密接口及会话撤销行为 |
| `GET /api/v2/auth/sessions` | 复用本人有效会话查询 |
| `DELETE /api/v2/auth/sessions/{id}` | 复用单会话退出，继续限制所属用户 |
| `POST /api/v2/auth/sessions/revoke-others`（新增） | 事务内撤销当前用户除当前会话外的其他有效登录，返回实际退出数量 |

资料写接口使用独立请求结构，拒绝未知字段；不得直接暴露包含 enabled 的管理员 AccountPatch。客户端不能指定 user_id、username、role、enabled 或资源归属。仅允许网页登录会话访问，播放器 Key 不具备个人资料修改权限；写操作执行现有 CSRF 校验。

昵称更新复用已有事务、用户版本校验、审计及公开目录／歌单同步失效逻辑；沿用 If-Match 约定，版本过期时提示刷新本人资料，不静默覆盖管理员或另一标签页的修改。未变化的昵称不产生额外版本或同步事件。

批量退出在事务中限定当前用户和非当前会话，重复执行可返回零；记录实际操作人及数量，不记录 Cookie、令牌或密码。会话失效后复用现有登录失效处理。

资料继续保存在现有 SQLite users 表中，会话继续保存在 sessions 表中。按当前范围预计无需增加数据库字段或修改 schema；开发时复核，不能为页面展示注册时间而把 updated_at 当成改密时间。

- 数据验收包括重启后昵称仍保留、同名账户仍独立、改密后旧会话失效而同一 Key 可继续使用、批量退出不影响其他账户。
- 每阶段通过相应验证后更新清单并本地提交。完整回归优先由后续明确授权推送触发 Actions；本地完成不等于 CI 或云端更新完成。
- 计划记录阶段仅检查文档后提交；当前开发阶段按功能做针对性验证，不运行无关测试。未获本次发布授权前，不调整发行版本号、不推送、不发布、不连接云服务器。
- 正式发布需要另行明确授权，并在发布时核对版本、发行说明、Actions 与资产；由用户在云端网页确认更新。
