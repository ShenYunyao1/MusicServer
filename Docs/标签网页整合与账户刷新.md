# 标签网页整合与账户刷新

日期：2026-10-28。对应 [标签与筛选计划](曲目标签与组合筛选开发计划.md) P05。本地验证使用隔离 schema 8；默认程序仍为 schema 7，不代表正式服务已启用。

## 页面入口

- 全局曲库保留搜索、范围与筛选抽屉，新增“标签词典”。列表在标题下显示最多三个公共／本人标签及剩余数量；点击标签可进入组合筛选，详情可查看完整标签。
- 标签操作沿用右键、键盘菜单和触摸长按，不插入推动列表的顶部操作栏。390px 使用单列词典编辑器及可滚动对话框。
- 词典按作用域、分组搜索和分页。管理员维护公共词条、分组；成员可查看公共词条并管理自己的个人词典。支持逐行别名、重命名、删除和同组合并。被引用删除拒绝、版本冲突保留草稿；重新读取版本后由用户核对、再次确认，不自动覆盖。
- 合并需选择同组目标并确认，提交源和目标版本；标签 ID、曲目 UUID、源文件和上传者不因重命名改变。
- 登录先探测标签能力，再执行 URL 的筛选条件和首次目录请求。schema 7 打开含组合条件的地址明确提示不支持，不静默退回全库。

## 账户范围刷新

会话专用 `GET /api/v2/tag-sync` 返回：

```json
{"account_id":"当前账户UUID","library":10,"public":4,"personal":2,"saved":"摘要"}
```

`library` 为曲库修订；`public` 为公共词典／关系修订；`personal` 只属于本人；`saved` 是本人保存条件 ID 和版本集合的稳定 SHA-256 摘要，不返回名称、规则或资源 ID。无变更写入不改变修订。标签组修改也更新公共修订。

接口在同一事务中检查 schema 和当前会话，再计算响应；支持 ETag／If-None-Match／304，始终 `no-store`。停用、撤销或过期的会话不能借条件请求获得 304；API Key 拒绝，不能指定其他账户，schema 7 返回 `TAGS_UNAVAILABLE`。

网页可见时约每 15 秒请求一次这个小响应，恢复可见或网络连接时补查。目前使用现有 JSON 请求器比较修订，尚不发送条件 ETag。未变化不重读页面；曲库／公共／本人标签变化才重新读取当前曲库第一页，公共变更另取分组并清理标签名称缓存。**这是修订驱动的当前页面刷新，不是逐条标签变更日志推送。**

保存条件的变更不改变当前已应用的规则，因此不会重读曲库；每次打开抽屉直接读取保存列表。其他账户的个人整理不改变本人的基线，也不唤醒公共事件流。首次检查与曲库响应中的事务基线比较，避免初次加载和第一次轮询之间的变化被漏掉。

打开编辑对话框、创建／编辑歌单或排序时延迟应用刷新，保留未保存草稿和原乐观版本；关闭后再处理。曲目详情可只刷新标签区域。失败保持旧基线以便下一轮重试，不能把失败确认成已同步；退出登录清理状态并丢弃迟到响应。

## 有界列表摘要与旧协议

`POST /api/v2/track-query` 的每条 `items` 增加会话专用投影：

```json
{"tag_summary":{"items":[{"id":"标签UUID","name":"摇滚","scope":"public","group_id":"genre"}],"total":4}}
```

空摘要为 `items:[]`、`total:0`。服务端在读取分页结果的同一事务中对最多 100 首做一次有界查询，排除删除和人工忽略的关系；公共优先，按分组顺序、名称和 ID 稳定取前三项。不会逐首额外发 HTTP 请求。

个人标签变更不增加公共 `Track.Version`；网页保留同版本完整曲目详情时，仍采用最新分页摘要，避免旧缓存盖回新个人整理。这个字段不写进通用 `Track`、公开歌单或 Key 接口。

旧播放器继续使用既有曲目、歌单、Sync1／对象 Sync2 和音频请求。公共关系修改可产生受影响曲目的旧格式同步记录；个人整理不产生共享增量，词典改名不改变曲目投影。音频 UUID、摘要、格式、实际内容、媒体 ETag／304 及既有 `genre` 保持。原生播放器固定提交矩阵和正式 schema 8 安装门禁仍留在 P06／P01 安装验收。
