# 公开歌单与订阅开发计划

日期：2026-10-23。用户已确认第一期方案并授权实施。

## 范围与规则

第一期实现平台内公开歌单、订阅、公开详情链接、Key 显式授权及 MusicPlayer2 订阅状态。公开仅对本服务器已登录账户可见；新歌单默认私有。指定账户邀请、“仅分享”属性、匿名互联网分享和协作编辑留待后续。

订阅关联原歌单 UUID，作者修改后跟随更新。作者个人备注不公开；订阅者备注按账户单独保存，不能修改源歌单结构。用户不能订阅自己的歌单。

转私有／作者停用时保留订阅及 Key 授权记录，但暂停其效力；重新公开／重新启用后恢复。用户取消订阅时清除相关 Key 授权，重新订阅需重新授权。源歌单删除后保留最小失效记录，订阅者可清理。管理员接管后转私有，由新所有者决定是否重新公开。

目录最多每五分钟检查一次，仅页面可见时检查，首次访问立即加载，保留手动刷新。分页摘要加专用目录修订号／ETag，避免加载全库；订阅操作直接更新本人状态。详情、封面、Key 同步和媒体读取实时判断有效权限。全局曲库及其他歌单授权独立，已有下载文件不能收回。

## 数据与交付约定

版本拟定 0.12.0，SQLite schema 6，API 仍为 `/api/v2`。新增公开属性及索引、订阅表（账户／源 UUID 唯一、最小已发布名称快照）、订阅个人备注表；订阅不复制曲目成员。公开目录版本只在摘要或可见性变化时更新。

按现有开发约定不迁移 schema 5，旧测试库保持拒绝打开且不被改写。最终更新运行程序前停止旧服务，旧测试库留在 build 内隔离归档，使用全新测试库；管理员仍使用 admin，密码由用户在初始化终端设置。隔离验证不得使用现有账户或媒体作为测试夹具。

服务器使用原歌单 UUID 输出只读订阅视图，增加 `read_only`、`subscription_status`、`subscription_reason`、来源显示名；失效视图不包含曲目、封面或后续私有元数据。客户端显示失效状态、禁用对应歌单播放入口，正确处理同步重置与缓存；其他有效授权下相同曲目仍可访问。

## 实施清单

- [ ] PS01：schema 6、公开属性、订阅关系、账户备注、公开／私有切换和事务审计；默认私有、重复订阅、自订阅、删除失效及取消清理的 Go 回归。
- [ ] PS02：统一详情／媒体／封面／同步／Key 授权权限，公开只读投影和失效投影、个人备注隔离；覆盖转私有、重新公开、停用／启用、接管、取消订阅和游标重置。
- [ ] PS03：分页公开目录、专用版本与 ETag；读取本人订阅、订阅／取消接口，公开分享地址及登录后保留目标。验证旧 ETag、权限收回和缓存不会越权。
- [ ] PS04：网页公开目录、“我创建的／我订阅的”页签、只读详情、订阅／失效／恢复、可见性编辑与公开链接复制、Key 订阅授权分组；验证五分钟刷新、隐藏页暂停、返回及手机布局。
- [ ] PS05：MusicPlayer2 协议、快照／增量缓存、失效标识和播放入口，保留其他有效歌单访问；新增服务端联合回归并在客户端仓库提交。
- [ ] PS06：完整 Go／vet、网页多账户／触屏、原生客户端同步与编译验证；更新 README／更新日志，按规范固定路径编译与客户端打包；初始化新测试库后核对 8080／LAN 的版本与提交标识。
