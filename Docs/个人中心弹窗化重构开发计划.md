# 个人中心弹窗化重构开发计划

日期：2026-10-30。用户确认先前个人中心重构方案，并补充资料、安全修改通过独立弹窗，避免正常切换页面误报未保存。随后明确要求完成后发布：阶段验证及本地提交后推送main与匹配版本标签，Actions全部通过并核验正式资产后交付；不操作云端。

## 页面与操作

顶部只读账户摘要（头像、昵称、登录名、角色）及容量／上传状态摘要。四页签：基本资料、存储与上传、账户安全、登录管理。基础信息用文本而非可编辑输入框；存储额度单列显示已用／额度／剩余和有限额进度，不限额不显示百分比。容量统计规则保留原始上传者语义。

编辑资料弹窗统一昵称及头像，裁剪在弹窗内完成，裁剪使用只更新草稿，统一保存时后台同一事务提交。邮箱绑定／更换／验证及修改密码各自独立弹窗。登录管理只读列表＋退出确认。页面本身无持久可编辑表单，邮箱发码状态保留在服务器，密码、验证码、图片对象与草稿在弹窗关闭时清空。

弹窗保存后关闭并局部刷新；取消／关闭有真修改时仅在弹窗内显示一次“放弃修改／继续编辑”，不调用原生confirm。保存中禁止关闭；版本冲突保留草稿并提供明确重新读取。内部路由正常切换不弹未保存提示；弹窗打开时背景不可操作，浏览器刷新／关闭只在弹窗存在真实草稿时保护。未修改、自动填充旧隐藏表单、已取消编辑均不触发页面级保护。延迟响应按账户＋弹窗代际隔离。

## 接口与兼容

复用现有邮箱、密码、会话、存储与头像读取接口。新增 `PUT /api/v2/auth/profile` multipart字段 `display_name`，可选 `avatar` 或 `remove_avatar=true`，发生头像变更时必传 `avatar_version`；If-Match为当前用户版本。响应 `{user,csrf_token,avatar:{version,has_avatar,url}}`。后台事务内复核真实会话和用户／头像版本，再原子写入昵称及头像；任一失败全部回滚。保持旧auth/me及头像接口可用，保持schema 8，无数据库迁移或重建。
