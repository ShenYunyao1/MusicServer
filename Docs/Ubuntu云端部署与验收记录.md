## 验收规则

只修改 MusicServer 的目录与配置；现有代理及其他应用由原配置继续管理。测试数据使用明确标记，初始化正式管理员前核对并隔离，不能把测试密码留给用户使用。正式管理员已由用户创建，此后验收脚本不得重置正式数据。没有完成的云端用例不提前勾选。

首次部署后，普通主程序更新从网页确认并调用同一独立更新器；更新器本身、root 服务模板和代理配置变化，通过 SSH 部署经过验证的对应文件。无域名阶段使用本机独立端口转发，避免与本地开发的 8080 冲突。

无域名阶段，本机通过 SSH 隧道访问 `http://localhost:18080/`：

```sh
ssh -N -L localhost:18080:127.0.0.1:8080 <SSH主机>
```

该终端保持运行即可访问；关闭隧道只中断本机访问，不停止云端服务。当前工作区的私有连接助手位于忽略的 build 目录，不随源码分发。

日常升级：发布新的兼容 schema 7 的签名 Release 后，登录“系统设置 → 程序更新”，手动检查并选择安装，服务会下载、校验并自动重启。普通主程序修复不需要重复安装整个服务；root 更新器、服务模板或协议改变时才另行通过 SSH 更新组件。

```sh
systemctl status musicserver.service musicserver-update.path musicserver-update-recovery.timer
journalctl -u musicserver -u musicserver-update --since today
cat /var/lib/musicserver-update/job.json
```

公网域名及 HTTPS 入口尚未配置；有域名后再设置外部 origin 和反向代理。数据库备份不包含媒体，正式使用后需要分别备份数据、媒体及配置。
