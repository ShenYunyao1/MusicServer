# 初版使用与验证

本文记录初版行为。2026-10-08 的播放器适配 0.7.0 已改为完整歌单播放和按需缓存，当前操作及验收见 [播放器 0.7.0 使用与验证](播放器0.7.0使用与验证.md)。

本版范围是 Go 服务端与 MusicPlayer2 Windows 客户端，ESP32 暂缓。

## 快速使用

1. 按 `server/README.md` 启动服务端。开发测试地址：`http://127.0.0.1:18080`，测试密钥：`dev-test-key`。
2. 启动 `MusicPlayer2/x64/Debug/MusicPlayer2.exe`。Debug 版本的工作目录须设为 `MusicPlayer2/MusicPlayer2`，以加载上游的语言与界面资源。
3. 进入选项设置 → 最后的“服务器”页，填写地址、API Key 和缓存目录；“测试连接”会检查认证，点击“应用”或“确定”保存。
4. 打开媒体库 → 最后的“服务器”标签，点“刷新”。左侧是歌单，右侧是曲目；歌单描述、曲目注释与歌单内注释显示在下方。
5. 选择曲目并点击“播放选中”，或双击曲目。客户端先完整下载并校验 SHA-256，再交给 MusicPlayer2 原播放内核。
6. “离线保存歌单”下载整个当前歌单。“取消任务”保留已完成的缓存。网络失败时刷新会读取已保存快照，已缓存曲目仍可播放。

配置文件：播放器配置目录下的 `remote-library.json`，API Key 使用 Windows DPAPI 加密，绑定当前 Windows 用户。换机器或 Windows 用户后需重新填写密钥。
缓存默认位于配置目录下的 `remote-cache`；按服务器地址与密钥隔离，各目录包含 `library.json`、以内容哈希命名的音频和同名 `.lrc`。可以在播放器停止后手动清理缓存目录。

## 开发与构建

```powershell
cd D:\Develop\Study\MusicPlayer
.\server\build.ps1
.\Docs\build-player.ps1
```

已验证的 Go 工具链：`D:\Develop\Runtimes\Go1.26.8Full`。脚本只设置当前进程环境，结束后恢复。当前用户全局 `AppData/Roaming/go/env` 曾返回 APPX 加密访问错误，脚本通过 `GOENV=off` 使用独立环境，保留用户全局文件。C++ 使用 Build Tools 编译器与 Professional 安装中的 MFC 路径，详见构建脚本。

Debug 空歌单启动时，上游 `SongInfo.h:158` 的非空路径断言仍可能触发。本次联调在隔离的便携配置中预置有效本地曲目，不修改用户已有播放器配置，也没有禁用断言。新用户建议先导入一首本地曲目。

## 验证记录

- Go 自动测试覆盖认证、歌单查询、Range 下载、元数据/歌词/注释持久化、重扫保留修改与移除记录、超过 2 MiB 的上传、持久化失败回滚、音频与歌词符号链接越界保护。
- `go test ./...`、`go vet ./...`、服务端构建和 MusicPlayer2 Debug x64 编译已通过。C++ 保留上游已有的类型转换警告。
- 只读扫描 `D:\Download\音乐下载\MusicPlayer目录`：438 首音频，约 2.96 GB；下载 Range 测试收到 206 和指定字节数。
- 在实际桌面界面保存服务器配置、同步 438 首曲目、选择并播放《惊鸿一面》。下载约 4.50 MB 音频与同名歌词，缓存 SHA-256 与服务端内容哈希一致。
- 最终版本再次验证错误密钥显示 HTTP 401、正确密钥连接成功、重复刷新快照保存成功，并下载和打开另一首《The Phantom Of the Opera》。
- 停止服务端后刷新，界面明确显示离线模式，并成功再次打开已缓存曲目；测试结束停止播放及测试进程。
- 初版联调修正了快照文件关闭后才能在 Windows 替换、初始化调用消息处理函数引发重入、子页 `DS_CONTROL` 与上游 Tab 容器焦点处理不兼容的问题。

真实音乐目录仅用于扫描和下载，上传与删除等写入测试使用临时目录，原始音频和歌词未被改写。
Web 管理页已进行 JavaScript 语法检查和对应 API 自动测试；尚未对浏览器中的所有交互做完整验收。

## 当前边界

手动刷新；修订号变化时返回完整快照。首次播放完整下载，尚无边播边缓存、断点续传、缓存自动容量控制或后台定时同步。
关闭正在执行网络任务的页面可能等待当前请求的超时（15 秒），完成的缓存保留。第一版没有多用户、转码和外部歌词抓取。
服务端字段修改显示在服务器媒体库页；播放主界面的标签仍优先来自原始音频的嵌入式标签，暂不向原音频写回服务端元数据。
服务端源码和 Docs 位于工作区外层；上游 Git 仓库只覆盖 `MusicPlayer2` 子目录，后续提交时需单独纳入外层文件。
