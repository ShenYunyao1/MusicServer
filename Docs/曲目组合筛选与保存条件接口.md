# 曲目组合筛选与保存条件接口

2026-10-28，P04 本地实现。正式服务器仍为 schema 7，页面隐藏入口，接口返回 `503 TAGS_UNAVAILABLE`。以下行为在私有迁移测试库验证；没有推送、发行或云端更新。基础标签及批量契约见 [标签接口](曲目标签接口与权限.md) 和 [打标与导入](曲目标签打标与导入接口.md)。

## 结构化条件

`TrackFilter` 必须含 `version:1`，不接收任意 SQL 或表达式字符串。

| 字段 | 含义及限制 |
| --- | --- |
| `q` | 现有标题／歌手／专辑／genre 关键词，最多 256 字符 |
| `range` | `all`（默认）、`mine`（原始上传者本人）、`managed`（当前管理者本人）、`orphan`（未加入本人歌单）、`missing`（仅管理员） |
| `tags` | 最多 12 个分组子句，所有 include／exclude ID 合计最多 64 个 |
| `artists`、`albums` | 各最多 20 个精确取值，每项最多 256 字符；同字段任一匹配，不拆分名称中的逗号或斜杠 |
| `formats` | 已支持音频格式的扩展名，不带点 |
| `duration_min_ms`、`duration_max_ms` | 非负毫秒数；最大值不能小于最小值 |
| `uploaded_by` | 原始上传账户 UUID，仅管理员可使用；接管不改变原上传者 |
| `has_lyrics`、`has_cover` | 可选布尔值；省略为不限 |
| `untagged_public`、`untagged_personal` | 尚无有效公共标签／本人个人标签；不等同于未知风格，也不查看别人私人标签 |

标签子句为 `{scope,group_id,match?,include_ids?,exclude_ids?}`。scope 必须为 `public` 或 `personal`，group_id 显式指定；同一作用域／分组不可重复。match 默认为 `any`，也可选 `all`。子句必须至少有一个 include 或 exclude；清空分组时应显式移除整个子句，顶层无 tags 才表示无标签约束。

同组 include 按 any／all 匹配，exclude 排除任意指定标签；跨组及其他字段同时满足。合并标签会解析为目标 UUID 并返回 `redirects:[{from,to}]`；客户端明确提示后更新 URL。合并后若包含与排除落在同一 UUID，条件保持矛盾而返回零结果，不自动删条件。

不存在和越权 UUID 统一返回 404。本人有权读取的已删除词条或坏合并引用返回 `409 FILTER_REFERENCE_INVALID`。两者都不能被当成“忽略此条件”。私人词条只属于当前账户，管理员没有跨账户浏览权。

## 查询、计数和分页

全部接口要求账户会话，写方法及 POST 查询沿用同源 CSRF；API Key 不开放。POST 虽为只读查询，仍需要 `X-CSRF-Token`。JSON 最多 32 KiB，拒绝未知字段、额外 JSON 和 URL 查询参数；需要 If-Match 的修改不接受重复版本头，不缓存响应。

`POST /api/v2/track-query`：

```json
{"filter":{"version":1,"range":"all","has_cover":true},"sort":"title","direction":"asc","offset":0,"limit":50}
```

sort 白名单为 `title/artist/album/duration_ms/modified_at`，默认 title；direction 为 asc／desc，默认 asc。末级始终按 UUID 升序稳定排列。offset 为 0–1,000,000，limit 默认 50、最大 100。响应 `{items,total,offset,limit,baseline,redirects}`，items 为分页基础投影，不带完整歌词，成员不获得服务器路径。

baseline 为 `{account_id,library,public,personal}`，绑定账户、全局资料修订、公共标签修订及本人的个人标签修订。继续分页可传上次 baseline；不一致返回 `409 FILTER_SNAPSHOT_CHANGED`。网页会明确提示并重新读取第一页，避免混用不同数据版本。其他账户的个人标签变化不会改变自己的个人 baseline。

`POST /api/v2/track-facets` 接收 `{filter,scope,group_id,q?,offset?,limit?,baseline?}`，响应 `{items:[{tag,count}],total,offset,limit,baseline,redirects}`。只移除当前 scope／group 的标签子句后统计，其余条件和权限不变；不漏掉分页之外的曲目。词条可显示 0 个匹配，名称／别名搜索和分页在服务端完成。计数、分页及 baseline 在同一事务中读取。

## 个人保存条件

| 路径 | 方法 | 行为 |
| --- | --- | --- |
| `/api/v2/saved-track-filters` | GET / POST | 列出本人条件；创建 `{name,filter}` |
| `/api/v2/saved-track-filters/{id}` | GET / PATCH / DELETE | 读取、修改 `{name?,filter?}`、删除本人条件 |

最多 100 条／账户，名称最多 64 字符，按 NFC／case folding／空白归一做账户内名称唯一检查；规则 JSON 最多 16 KiB。PATCH／DELETE 要求 If-Match，缺失 428、格式错误 400、旧版本 409；名称重复返回 `FILTER_NAME_EXISTS`。授权先于对象版本检查，他人的记录统一 404。真正无变化不增加版本或审计。

记录含 `id/name/filter/version/created_at/updated_at/validation`。持久化原始规则；validation 含 `valid/code/redirects/resolved_filter`。GET／List 不自动改写 UUID 或版本。引用失效时仍保留可编辑草稿并标无效，网页拒绝直接应用，但可载入草稿显式修复、仅重命名或删除；替换规则必须重新完整验证。

仅保存筛选规则，不保存页码、临时 baseline 或排序，不创建歌单、不授权 Key。网页 URL 的 `tf/q/filter/sort/dir/offset` 用于恢复当前浏览条件；不把 baseline 或凭据写入 URL。账户切换清理页面状态、标签名称缓存和未完成响应。

保存条件不会改变公共修订号或通知其他用户；私人审计不包含名称、条件、曲目／标签／条件记录 ID。会话撤销仍返回 401，数据库异常仍返回失败，不能伪装为可应用的无效或空条件。

## 与批量整理衔接

P03 `TagBatchQuery` 新增 `conditions` 和可选 `baseline`：`{query:{conditions:TrackFilter,baseline?}}`。不能同时传旧 q／filter 字符串。预览在同一事务内运行完整条件，冻结全部匹配 UUID 及标签版本，上限仍为 5,000 首；后续新匹配曲目不加入，未修改成功项不重复执行。其余确认、取消和重试规则沿用 P03。
