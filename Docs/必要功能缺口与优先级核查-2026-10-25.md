## 优先补齐

| 优先级 | 功能 | 当前能力与缺口 | 建议验收目标 |
| --- | --- | --- | --- |
| P1 | 完整备份与恢复 | 已有 SQLite 一致快照、完整性检查和更新前数据库备份；手动备份页面返回服务器路径。尚无定时备份、保留策略、媒体与配置的一体备份管理或独立恢复工具。 | 配置定时／保留数量；可取回备份；同时保存媒体及必要配置清单；在隔离目录恢复并验证账户、UUID、歌单、音频及重新登录；至少保留一份服务器之外的副本。 |
| P1 | 磁盘容量与配额管理 | 已有单文件大小及 Key 下载并发限制，更新器下载前会检查空间；普通上传无全站低水位保护／用户空间配额，备份和旧发行目录也不自动清理。 | 先展示媒体、暂存、备份、发行包的空间与剩余容量，低水位拒绝新上传并给明确提示；清理保留当前与回退版本；多人使用时再定义账户计费归属及配额，避免共享去重文件重复计费。 |
| P1 | 网页与两端兼容性的 CI | 服务器 Actions 已运行 Go、vet、部分 Linux race、安装／回退及签名打包；现有 Chromium 网页回归仍仅单独运行。播放器真实服务器测试固定为 0.16.2 提交。 | 在 Actions 接入现有管理页、个人中心、实时刷新和删除专项；播放器同时验证受支持的固定基线及最新服务器候选，保留独立临时数据，测试失败阻止正式发布。 |
| P2 | 上传断点续传与任务恢复 | 已有真实发送进度、等待校验阶段及取消；当前仍是整文件 multipart 请求，连接中断后重试需重新发送，刷新页面丢失本地待处理队列。 | 按上传任务记录偏移、校验及到期时间；支持暂停、重新连接后续传、重试与队列恢复；浏览器需要重新选择本地文件时明确提示，不承诺刷新后仍能任意读取原文件。 |
| P2 | 普通曲库和私人歌单的大库访问及刷新 | 播放器已有分页／游标同步，公开目录已有分页与 SSE；网页普通曲目／歌单读取仍完整加载，前端筛选和重绘。社区 SSE 没有同步普通全局曲库和本人私人歌单。 | 服务端分页、排序和必要搜索索引；列表虚拟化；普通曲库及私人歌单按当前视图补取变化，保留焦点和滚动，不能把社区实时刷新等同于全站实时刷新。 |
| P2 | 播放器同步进一步减少重置 | 已有分页、增量、缓存优先及每小时检查；Key 同步绑定包含可见曲目集合，集合变化可能使游标失效并重新获取快照。 | 区分普通内容变化与授权变化，细化歌单／曲目对象级增量；授权撤回继续清理或安全重置，不能为了少传数据删除现有权限校验。 |

P1 表示进入多人、长期云端使用前优先补齐，不代表当前已经发生故障。P2 可按实际曲库规模和网络体验实施。断点续传可减少断线后的重复传输，不能提高实际带宽上限。

## 长期保存真实数据前需要决定

**数据库版本迁移。** 现有初始化拒绝旧 schema，自动更新器也拒绝跨 schema 安装。这符合目前“测试数据、不兼容旧格式”的既定规则，不应擅自改变。若决定长期保存真实账户与歌单，再实施版本化迁移、迁移前备份及失败恢复，并明确允许的回退边界；此项不是当前同 schema 更新的故障。

## 可后置的产品扩展

- 协作编辑歌单：当前按已确认范围提供只读分享，编辑权限及冲突合并后续实施。
- 匿名分享链接：当前公开目录／分享链接均要求站内登录；匿名访问需要单独定义有效期、权限和撤销。
- 个人头像、邮箱找回、自助注册、播放历史／独立喜欢标记：均未形成完整当前产品流程，可在主链和运维能力稳定后按实际需求选择。
- 转码及边下载边播放：当前服务器已有 Range 读取；Windows 播放器使用完整下载、校验后缓存播放，不能将“Range 接口存在”当作客户端已支持边播边缓存。

## 推荐实施顺序

1. 用户明确要求后发布已完成的账户／Key 变更，并执行新增 CI 检查。
2. 下一功能阶段先做备份恢复与磁盘容量保护，同时接入现有网页自动回归。
3. 根据当前网络体验推进上传断点续传。
4. 随曲库规模推进分页、普通视图刷新及播放器同步细化。
5. 正式长期保留数据之前，另行确定 schema 迁移规则。

此核查不代表已授权开发上述新增功能，也不包含推送、发布或云端运维操作。

## 核查依据

- `server/internal/music/admin.go`、`administration.js`：数据库备份及页面仅返回备份路径；`server/deploy/README.md`：媒体／配置另行备份、发行及备份手动清理。
- `server/internal/music/types.go`、`staging.go`、`upload-progress.js`：单文件上传限制、暂存与整文件 XHR，没有上传偏移续传协议或账户配额配置。
- `server/internal/music/server.go`、`library.js`、`community-realtime.js`：普通曲库完整响应及前端筛选；社区通知限定公开／订阅／邀请视图。
- `server/internal/music/sync.go`：Key 的成员集合参与游标绑定；`sqlite.go` 及 `server/internal/update/install.go`：schema 限制。
- `.github/workflows/server-release.yml`：目前没有 Playwright 网页作业；`MusicPlayer2/client-release.json`：联调基线为 0.16.2／`0ea3fba05b02d12926381b6d8f93f91df57e2aac`，客户端独立工作流按此提交检出服务器。
- [SQLite VACUUM INTO 官方说明](https://www.sqlite.org/lang_vacuum.html)：生成一致的数据库快照，不等于完整媒体和配置备份。
- [tus 续传协议](https://tus.io/protocols/resumable-upload)：以任务偏移查询及后续上传实现断点续传，可在后续设计时参考，当前没有引入该依赖。
