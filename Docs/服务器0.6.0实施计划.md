# 服务端 0.6.0 实施计划

目标：补齐上一轮审查中优先级较高的并发限制、权限 scope、排序持久化、设置、媒体资源、上传暂存去重和调用统计，同时兼容本地歌曲常见的外置歌词与外置封面。

## 完成标准

- API Key 的 scope 在每个读写接口实际生效；同一 Key 的活动请求数达到上限时返回 429，并在请求结束后释放计数。
- 调用统计按 Key 持久化到 SQLite，能通过管理员接口查询，统计失败认证、成功/失败状态和响应字节数。
- 歌单显示顺序保存到 SQLite，重启后与拖拽顺序一致。
- 设置页能读取媒体目录，修改 ffprobe 路径、上传限制和外置资源扫描开关；媒体目录为启动参数只读，修改需要管理员权限和对应 scope 并持久化。
- 曲目保存时包含时长、码率、采样率、声道、位深和封面资源；封面支持内嵌图片与常见外置图片安全解析。
- 扫描同名 `.lrc`、`.elrc`、`.txt` 外置歌词；优先级为人工 > 外置 > 内嵌。封面优先级为人工 > 内嵌 > 同基名图片 > 精确作者/专辑 `AlbumCover` > `cover`/`folder`/`albumcover` 图片。
- 上传先进入暂存区并返回解析预览，确认后才移动到媒体目录和写入曲目；相同内容哈希不会重复导入。
- 管理后台增加设置、统计、封面/技术参数和上传预览入口。

## 步骤

1. 扩展 `Track`、`Playlist`、`Library` 和 SQLite schema，增加 `sort_order`、`assets`、`settings`、`upload_staging`、`api_call_stats` 表；迁移只允许当前 schema 版本，不恢复旧 JSON。
2. 接入 scopes、请求并发租约和统计中间件，增加接口错误码和回归测试。
3. 扩展音频标签解析、外置封面查找、图片大小/像素校验及技术参数读取；增加真实歌曲探针。
4. 增加歌单排序接口、设置接口、封面资源接口和统计接口。
5. 将上传改为 stage/preview/commit/DELETE 生命周期，按 SHA-256 去重并做失败清理。
6. 更新管理页的设置、统计、封面预览、技术参数、上传确认和歌单拖拽保存。
7. 运行 `go test ./...`、`go vet ./...`、构建、真实标签探针和隔离 API/重启测试；更新 `update.md` 与功能审查。

## 外置资源规则

- 歌词：同路径同基名 `.lrc`、`.elrc`、`.txt`，大小限制 2 MiB；人工 PATCH 后不被重扫覆盖。
- 封面：同基名 `jpg/jpeg/png/gif/webp`，匹配标签的 `AlbumCover - 作者 - 专辑.*`，以及同目录 `cover.*`、`folder.*`、`albumcover.*`；单文件限制 8 MiB，解码像素限制 20 MP，拒绝路径外文件和未知格式。
- 同目录存在多个候选时按上述文件名和扩展名顺序选择，并在 API 中标记来源。
