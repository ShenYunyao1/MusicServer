# 外置歌词与封面处理

服务端 0.6.0 将歌词和封面作为曲目的关联资源管理，不要求把资源重新写入原始音频。原音频的内容哈希保持不变。

## 媒体目录扫描

推荐把每首歌的文件放在同一目录，使用相同基名：

```text
音乐目录/
  爱殇.mp3
  爱殇.lrc
  爱殇.jpg
```

| 资源 | 候选文件 | 优先级 |
| --- | --- | --- |
| 歌词 | 同基名 `.lrc`、`.elrc`、`.txt` | 人工修改 > 外置文件 > 内嵌歌词 |
| 封面 | 同基名 `.jpg`、`.jpeg`、`.png`、`.gif`、`.webp` | 人工指定 > 内嵌图片 > 同基名图片 > 标签匹配专辑封面 > 目录共享封面 |
| 专辑封面 | `AlbumCover - 作者 - 专辑.扩展名` | 作者和专辑必须与曲目标签精确匹配，忽略大小写 |
| 目录共享封面 | `cover.*`、`folder.*`、`albumcover.*` | 用于同目录所有没有更高优先级封面的曲目 |

歌词和图片文件名忽略大小写。任意名称的图片不会因为出现在同目录就被当作封面，避免混合歌曲文件夹出现错配。混合目录应使用每首歌的同名封面；只在整张专辑目录使用共享 `cover.jpg`。

歌词支持 UTF-8（含 BOM）、带 BOM 的 UTF-16 LE/BE、GB18030；上限 2 MiB。图片上限 8 MiB、20 MP，校验实际格式，不只依赖扩展名。空白或无法读取的外置歌词允许回退内嵌歌词。`embedded_lyrics` 独立表示音频是否有内嵌歌词，即使最终显示的是外置歌词也不会改变它。

扫描开关位于服务器设置页。添加或修改目录内资源后需要重新扫描；目前没有自动目录监听。人工修改歌词、指定封面会保存为覆盖值，重扫不会覆盖；显式修改为空也会保留。

## 网页上传

浏览器不能读取没有被用户选择的相邻本地文件，因此只选择 `爱殇.mp3` 时，不会自动访问磁盘上的 `爱殇.lrc` 和 `爱殇.jpg`。

1. 同时选择音频、歌词、封面，或者选择/拖放整个文件夹。目录选择会保留相对目录以匹配同名资源，避免不同子目录的同名曲目串用附件。
2. 查看上传队列中关联的歌词和封面；文件名不符合规则时，可以在每首歌旁手动指定附件，也可以取消错误附件。
3. MP3 添加后自动在浏览器读取 ID3v2 标签、内嵌歌词和封面，立即显示本地预览；可以先整理标题、作者、专辑和风格，展开“歌词与注释”查看和编辑文本。已选择的外置歌词和封面也在浏览器中预览。
4. 点击“上传校验”才发送音频及附件到暂存区，查看服务器最终解析和校验结果；已有暂存可“重新校验”。其他音频格式在此之前显示等待服务端确认。
5. 点击“确认入库”才正式保存。修改附件会删除旧服务端暂存预览，需要重新上传校验；本地预览随附件重新解析。

网页自动选择同名资源、标签匹配的 `AlbumCover`，最后尝试常规目录共享封面。自动匹配的封面标记为 `external`，优先级低于内嵌封面；用户在歌曲旁手动指定的封面标记为 `manual`，优先级最高。不符合命名规则的图片/歌词必须手动指定。上传歌词保留 `sidecar` 来源。确认后歌词保存为媒体目录内音频旁的同名 `.lrc`；自动关联封面保存为同名图片及 SQLite 资产，手动指定封面保存为 SQLite 资产和人工覆盖，重启/重扫仍可读取。

相同音频 SHA-256 命中已存在曲目时不会新建第二条记录，也不会用本次附件覆盖旧曲目。需要更新已有歌曲资源时，在曲目管理中右键选择“更换封面文件”或“更换歌词文件”。

暂存保留 30 分钟，可主动取消；服务启动及每分钟清理过期文件和无记录的服务暂存文件。取消/失败不会修改原始本地文件。

## 浏览器本地即时预览（0.6.1）

MP3 的本地解析范围是 ID3v2 标签，包括标题、作者、专辑、风格、注释、内嵌文本歌词和图片。解析在用户的浏览器中读取已选择的 `File`，不会在添加文件时调用暂存上传接口，也不会增加曲目库记录。浏览器只能预览用户已明确选择或拖入的文件，不能自行访问音频附近的附件。

FLAC、Ogg/Opus、M4A、WAV 等格式的标签继续由服务端解析，本地队列显示等待服务端确认。MP3 中没有标签、标签异常或本地不支持的标签帧内容，也继续等待服务端最终确认；本地预览是上传前的整理参考，服务端仍负责资源格式和大小校验、内容哈希去重以及最终入库。

本地解析使用随服务器打包的 jsmediatags 3.9.7，不请求 CDN。BSD-3-Clause 许可保存在 `server/internal/music/vendor/jsmediatags-LICENSE.md`；本地补丁说明在 `server/internal/music/vendor/README.md`，补齐 COMM/COM、USLT/ULT 和 TXXX 描述后的 UTF-16 文本在缺少独立 BOM 时对 UTF-16BE 字节序的继承。

外置附件继续使用原有的同目录、同基名和共享封面规则。作者与专辑标签读取后，会重新尝试精确匹配 `AlbumCover - 作者 - 专辑.*`。封面保留人工指定 > 内嵌 > 自动匹配的优先级；歌词保留人工修改 > 外置 > 内嵌的优先级。用户取消某个自动附件后，不再自动关联该类附件；重新手动指定时使用用户的选择。

## API 与播放器

同步/曲目接口直接返回歌词文本与来源，封面通过 `cover_id`、`cover_mime`、`cover_source` 引用。封面下载需要 `media:read`，且播放器 Key 必须被授权访问使用该封面的歌曲所属歌单。

MusicPlayer2 远程库客户端把返回的歌词写为缓存音频旁的 UTF-8 BOM `.lrc`，所以播放器不需要区分服务端歌词来自内嵌还是外置。封面单独认证下载并验证 SHA-256，保存为缓存音频同名 JPEG/PNG/GIF 图片；封面变化或移除时同步清理旧图片，失败不阻止播放，已有封面可离线使用。当前播放器图片解码不支持 WebP，服务端仍可展示 WebP，桌面客户端跳过该格式。

## 验证记录

- 本机《爱殇》：网页同时选择 MP3、LRC、JPG，预览使用外置歌词并保留音频内嵌封面；预览阶段库记录仍为空，确认后在右键菜单中手工指定 JPG 封面；重扫、重复上传后仅保留一条曲目及其资源。
- 本机《Reply》：目录中的专辑封面按作者/专辑匹配，不应用到无关曲目。
- 自动回归覆盖歌词编码/大小写、图片校验、标签匹配、附件重启/重扫、事务失败重试、现存歌词保护和遗留暂存清理。
- MusicPlayer2 WinHTTP 黑盒回归验证认证下载、封面哈希、格式切换、损坏修复、超限/无权下载、更新/移除、授权撤销和断网复用；Debug x64 构建通过。

0.6.1 浏览器本地预览验证使用本机《麻雀》与《爱殇》样本：MP3 标签、内嵌封面、外置歌词及手工编辑在上传前显示，未触发暂存请求；实际《爱殇》样本没有内嵌歌词，因此界面正确显示“无内嵌歌词”，由外置 LRC 提供歌词。FLAC 样本在本地显示“等待服务端确认”，上传校验后使用服务端标签。选择/拖放、暂存确认、去重和手机布局通过。
