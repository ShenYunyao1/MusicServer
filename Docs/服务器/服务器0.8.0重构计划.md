# 服务器 0.8.0 重构

## 目标与边界

曲目 UUID 为永久主键，文件路径和内容哈希为属性。全新 SQLite schema 和 API 合约，不迁移或兼容旧库；拒绝旧 schema，不删除或重写旧数据。不修改实际运行实例、正式媒体目录或客户端仓库。

## 实施顺序

1. `server/internal/music/types.go`、`sqlite.go`、`store.go`：移除内存全库快照，使用 UUID、逐条事务写入、版本检查、变更日志及审计；建立新模型回归。
2. `scan.go`：后台扫描、进度/取消、锁外解析、变化检测、唯一哈希移动识别、单文件错误隔离、保留缺失记录及人工覆盖；无变化不增加修订。
3. `staging.go`、`cover_store.go`：锁外暂存、音频流验证、明确探测状态、确认时去重，封面独立保存。
4. `sync.go`、`server.go`、`access.go`：持久增量日志、授权绑定游标和分页快照，独立下载并发，条件写入，恢复、审计和备份接口。
5. `index.html`、`cmd/musicserver/main.go`：管理页接入新合约，扫描任务、恢复入口、审计/备份，显式匿名模式及公网认证检查，安全关闭。
6. `server/README.md`、`update.md`：记录新行为、破坏性变更、备份恢复流程；运行 Go 测试、vet、构建及浏览器脚本检查。

## 验收

- 重命名、移动后 UUID、歌单和人工修改保留；重复内容歧义不误合并。
- 扫描期间查询和编辑可用；取消不提交，文件失败不清空库，缺失文件可恢复。
- 单项修改不改写无关曲目/封面；失败回滚业务数据、版本、日志和审计。
- 增量同步包含删除；授权变化使旧游标失效；分页有稳定边界。
- 非音频上传拒绝；缺少探测工具时明确失败；暂存清理与确认无竞争。
- 下载不占用元数据并发；匿名模式显式开启且仅绑定回环地址。
- 备份包含一致数据库快照，能够打开并通过 integrity_check。

设备心跳租约和完整音频解码属于按需扩展，本次保留请求/下载限额，不提供单设备授权承诺。先保留 DELETE journal 模式，WAL 不作为本次优化前提。
