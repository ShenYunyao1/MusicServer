# 音频标签检查记录

检查日期：2026-10-07。检查目标是解释 MusicPlayer2 能显示作者与内嵌歌词，而升级前 server 只能从文件名和目录生成曲目信息的差异，并记录服务端解析器的验证范围。

## 检查对象与方法

真实样本目录：`D:/Download/音乐下载/MusicPlayer目录`。目录统计为 MP3 432 个、FLAC 5 个、WAV 1 个、同名 `.lrc` 428 个，没有 M4A 样本。歌曲只读打开，没有复制到仓库，也没有连接线上 server。

先使用 `D:/Program/ffmpeg/bin/ffprobe.exe -v error -show_entries format=format_name:format_tags:stream_tags -of json <path>` 做字段和歌词长度的交叉检查；歌词正文不写入记录。随后使用服务端 Go 解析器直接读取 7 个样本，命令如下（环境变量未设置时该测试会跳过）：

```powershell
$env:MUSIC_SERVER_METADATA_SAMPLES='D:/Download/音乐下载/MusicPlayer目录'
go test ./internal/music -run '^TestLocalAudioMetadataProbe$' -count=1 -v
```

测试只输出标题、作者、专辑、来源和歌词长度/行数，不输出歌词正文。

## 两个程序的差异

MusicPlayer2 的 `AudioTag.cpp` 按 MP3、FLAC、M4A、WAV 类型调用 TagLib 标签和歌词读取；`TagLibHelper.cpp` 将标签的 title、artist、album、genre、comment 直接写入曲目信息，并分别读取 ID3 `USLT`、FLAC `LYRICS`、MP4 `----:com.apple.iTunes:Lyrics` 和 WAV 内嵌 ID3。升级前 server 的 `readTrack` 只按文件名中的 `" - "` 分隔标题与作者、以父目录作为专辑，再搜索同名 `.lrc`、`.elrc`、`.txt`，所以真实标签一直没有进入服务端模型；例如没有空格分隔符的 FLAC 文件名不能可靠提供作者，带 `Adele - Rolling...` 的文件名还可能将字段解释反向。

当前服务端先读容器标签，再由外部歌词覆盖歌词正文；歌词来源记录为 `sidecar`、`manual` 或标签来源。检测到内嵌歌词但后来使用外部或人工歌词时，曲目仍可记录内嵌事实。

## 当前支持与边界

- 支持 ID3v2.2/2.3/2.4 的标题、作者、专辑、风格、备注；USLT/ULT、TXXX/TXX 歌词和 SYLT/SLT 的**毫秒**时间戳可读。SYLT 的 MPEG frame 时间戳没有音频解码器支持，因此保持为空。
- 支持 FLAC、Ogg Vorbis、Opus 的 `LYRICS`、`UNSYNCEDLYRICS`、`UNSYNCHRONIZEDLYRICS`；支持 WAV RIFF 中大小写不敏感的 `id3 ` chunk，并跳过大型 `data` chunk。
- 支持 MP4 `©lyr` 和 iTunes freeform Lyrics。MP4 extended-size atom 与 size=0 atom 当前拒绝；目录中没有真实 M4A 样本。
- 单条内嵌歌词上限为 2 MiB，标签读取预算为 32 MiB。ID3v1 中文历史本地编码不做猜测转码；WMA/ASF 标签、裸 AAC 流元数据不在本次范围内。
- WAV 只解析 RIFF/WAVE 的 ID3 chunk；LIST/INFO 等其他 WAV 信息块没有映射到曲目字段。
- 解析器预检查 FLAC/Ogg 图片声明长度、Vorbis `METADATA_BLOCK_PICTURE` 和容器边界，避免损坏封面长度触发大内存分配；图片内容本身不写入曲目模型。

以上限制表示解析失败时仍可安全回退到文件名/外部歌词路径，不代表音频解码、封面、时长、码率或采样率已经实现。
