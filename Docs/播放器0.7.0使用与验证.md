# MusicPlayer2 服务器适配 0.7.0

日期：2026-10-08。此次升级修改 Windows 播放器；服务端仍为 0.6.1，沿用现有同步、曲目与封面接口。

播放器仓库提交：`26c4c97`（服务器歌单整单播放与按需离线缓存）。

## 使用方式

1. 进入“选项设置 → 服务器”，填写服务器地址、API Key 和缓存目录，保存设置。Key 需要具备目标歌单授权及曲目读取、下载所需的权限。
2. 打开“媒体库 → 服务器”。已有同步快照时先读取本地歌单；首次没有快照时自动连接服务器。需要检查更新时点击“刷新”。
3. 选择左侧歌单，点击“播放歌单”或双击歌单。播放器载入完整队列，从第一首开始播放，按主播放器选择的播放模式继续切歌。右侧曲目用于浏览标签和注释，选择或双击曲目不会替换为单曲队列。
4. 关闭、重开媒体库，或切换媒体库标签页，保留上次歌单、曲目选择与曲目列表滚动位置；这些浏览操作不会重置当前播放队列、播放位置或暂停状态。
5. “刷新”会同步已关联服务器歌单的本地 Playlist 曲目和当前播放队列；新增曲目无需再次点击“播放歌单”，标题和作者即可显示。再次点击“播放歌单”仍会从服务器快照恢复完整队列，包括此前在主播放列表手动移除的曲目。
6. “离线保存歌单”是用户主动下载整个歌单的入口。普通播放不会触发整单下载或下一首预取。“取消任务”取消页面同步或离线保存任务；播放准备任务由暂停、停止和切歌操作分别控制。

## 缓存与断网规则

- 打开或恢复歌单只校验当前曲目的本地音频；明确播放或自动切到该曲目时，才允许下载缺失或损坏的缓存。
- 缓存先校验文件大小与 SHA-256。校验通过直接播放，包含封面在内的播放准备过程不发 HTTP 请求；没有缓存或校验失败才下载当前音频，再校验并替换缓存。
- 首次下载需完整完成才交给 MusicPlayer2 播放内核。此次没有加入边播边下载或断点续传。
- 服务器不可连接时跳过未缓存曲目，继续寻找已缓存曲目。连接传输失败后，对该服务器缓存空间暂停网络尝试 60 秒，避免每首曲目重复等待超时；手动刷新或播放重试可清除等待状态。
- 顺序播放到歌单尾部停止；其他模式允许依照模式继续寻找曲目，但一次连续失败遍历中每个索引最多尝试一次，没有可播放曲目时停止，避免循环跳过。
- 下载期间暂停保留暂停意图；停止、切歌、切换歌单使旧任务失效。旧下载结果不能恢复播放或覆盖新曲目。关闭媒体库不会取消播放任务。

## 文件与显示名称

缓存音频仍使用内容哈希命名。它是文件身份与校验依据，音频本身没有因此被加密。主播放列表和播放器标题使用“作者 - 标题.格式”等友好名称；标题缺失时尝试使用服务器原文件名，不改写原音频标签或批量重命名缓存。

服务器返回的标题、作者、专辑、风格、注释及技术参数用于初始化完整队列，媒体库 Playlist 页也从关联快照读取这些元数据，未下载曲目不会显示为未知。准备播放时写入快照歌词并关联快照封面；服务器歌词和封面优先，原音频内嵌资源可作为回退。服务器曲目不触发自动第三方歌词、封面匹配；手动搜索仍可使用。

主要文件：

| 文件 | 用途 |
| --- | --- |
| 播放器配置目录下的 `remote-library.json` | 地址、缓存目录和 Windows DPAPI 加密的 API Key |
| 服务器缓存空间下的 `library.json` | 已同步的浏览快照 |
| 服务器缓存空间下的 `browse.json` | 上次歌单 ID、曲目 ID 和滚动位置 |
| `内容哈希.音频格式`、同名 `.lrc` 与图片 | 校验后的音频和当前准备曲目的资源 |
| 缓存空间下的 `covers/封面内容哈希.图片格式` | 按内容 ID 暂存封面，刷新不会直接改写播放中的图片 |
| 播放器歌单目录下的 `server-服务器命名空间与歌单ID哈希.playlist` 与 `.playlist.remote.json` | 与服务器歌单 ID 关联的完整播放队列及元数据快照；刷新后复用同一文件并清理同一歌单的旧快照，不写入 API Key |

缓存空间按服务器地址和 Key 隔离；读取播放快照时也校验该空间，避免将旧服务器歌单绑定到其他服务器。更换 Windows 用户或机器后需重新填写 Key。

## 实现位置

- `MusicPlayer2/MusicPlayer2/RemoteLibraryVersion.h`：独立适配版本号 0.7.0，不替换上游播放器版本号。
- `RemoteLibraryClient`：本地校验、下载、歌词与封面资源、持久同步快照。所有实例的 HTTP 请求统一串行执行，包含设置页“测试连接”，适配 Key 默认并发数 1。
- `RemoteLibraryManager`：应用级任务队列、离线等待状态、播放快照绑定、页面状态。工作线程不访问窗口或播放内核；当前播放任务优先，主动离线保存按每首曲目拆分任务。
- `Player`：异步准备当前曲目，主窗口定时器在播放锁内处理结果，保留暂停和定位意图，处理失败跳过与停止。
- `ServerLibraryDlg`：整单播放、浏览状态恢复、显式刷新；刷新时同步已关联服务器歌单的本地快照和当前播放队列；窗口关闭与应用级播放任务的生命周期分离。

## Debug 空歌单断言修复（2026-10-08）

空默认歌单启动，以及从空歌单切换到服务器歌单时，保存播放历史会把空占位 `SongInfo` 转为 `SongKey`，触发 `SongInfo.h:158` 的非空路径断言。`Player::SaveRecentInfoToFiles()` 现在只在当前曲目路径非空时保存曲目键；空歌单保留默认空键。保留原有断言，不改变真实曲目的历史记录。

桌面脚本新增 `--empty-default-playlist`，使用空默认歌单并直接检测 Debug 断言对话框。修复前该用例在启动时复现原断言，尚未发出服务器请求；修复后两个报告场景及完整 Debug 桌面回归通过，Debug x64、Release x64 均构建成功。本轮第一次完整回归在连续失败用例等待超时，最终构建重跑全部通过；日志和配置保留在测试目录中。

## 媒体库 Playlist 元数据修复（2026-10-09）

媒体库 Playlist 页原本只从本地媒体库读取歌曲标签，因此新增但尚未下载的服务器曲目会显示未知标题和作者。现在读取关联歌单时加载其服务器元数据快照，并在本地标签读取后应用到曲目表。桌面回归新增刷新后检查媒体库 Playlist 页新增曲目的标题、作者及曲目数；修复前标题断言失败，修复后 Debug x64 与 Release x64 完整桌面回归均通过。验证目录为 `MusicPlayer2/x64/media-playlist-metadata-debug-green` 和 `MusicPlayer2/x64/media-playlist-metadata-release-green`。

## 当前限制

- WinHTTP 使用同步请求。停止或切歌会立即使旧结果失效，但正在等待连接或响应的工作线程要等请求返回或超时，后续下载和设置页同步连接测试可能因此等待。当前连接超时为 5 秒，发送/接收超时为 15 秒。
- 当前桌面图片解码器支持 JPEG、PNG、GIF 等，仍不支持 WebP。
- 歌单更新使用手动刷新；没有自动定时同步、缓存容量上限和自动淘汰。已完成缓存会保留，可在停止播放器后手动清理。
