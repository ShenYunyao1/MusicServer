# 增量同步协议 v1（库同步 + 实时视图）

状态：规范草案（随代码同步维护）。适用服务器：0.21.x（schema 9），库同步协议版本 `1`/`2`，实时视图协议无独立版本号。

本文件是客户端与服务端之间的**线格式权威说明**。仓库内此前的协议描述散落在设计与开发计划文档中，只说明意图，没有帧格式、错误表、兼容规则或可执行样例；本文件与 [`contracts/`](../../contracts/README.md) 一起补齐这些缺口。实现与本文冲突时以已发布代码为准，并应同步修正本文和契约。

> 可执行契约：`contracts/schemas/`（JSON Schema）、`contracts/examples/`（示例帧与报文）、`contracts/mock-server.mjs`（零依赖 mock）、`contracts/verify.mjs`（自检）。运行 `node contracts/verify.mjs` 即可验证全部样例和 mock 行为。

## 1. 范围

本协议覆盖两条客户端同步通道：

1. **库同步**：`GET /api/v2/sync`、`POST /api/v2/sync/tracks`。用于播放器/桌面端获取曲库快照、增量变化与批量曲目解析。
2. **实时视图**：`GET /api/v2/community/events`（SSE 唤醒帧）、`POST /api/v2/community/sync`（视图增量）。用于网页端在提交后只补取当前可见列表的变化。

不在本协议内：上传续传（`/api/v2/uploads/resumable`）、标签同步、备份/更新、媒体下载。上传续传目前只有设计文档，尚无同等契约；需要时另立协议文档。

术语：

| 术语 | 含义 |
| --- | --- |
| 快照（snapshot） | 某视图/库在某个 revision 的完整分页基线。 |
| 增量（delta） | 相对客户端持有的游标基线发生的新增、修改、删除、重排。 |
| 游标（cursor） | 不透明字符串，只能原样回传；禁止解析、拼接或持久化超出服务端声明期限。 |
| 绑定（binding） | 游标绑定的身份、凭证、权限版本与视图参数；绑定变化即 reset。 |
| reset | 服务端要求客户端丢弃该视图旧缓存，从响应重建。 |
| 帧（frame） | SSE 传输中的一条事件帧；本协议 `data` 恒为 `{}`，只作唤醒信号。 |

## 2. 通用 HTTP 约定

### 2.1 认证

| 通道 | 会话 Cookie | API Key | 说明 |
| --- | --- | --- | --- |
| `/api/v2/sync` | 允许 | 允许 | Key 需要 `library:read`；会话 GET 不要求 CSRF。 |
| `/api/v2/sync/tracks` | 允许 | 允许 | Key 需要 `library:read`；会话 POST 需要 `X-CSRF-Token` 且同源。 |
| `/api/v2/community/sync` | **仅会话** | 拒绝 | Key 调用返回 403 `SESSION_REQUIRED`；POST 需要 CSRF。 |
| `/api/v2/community/events` | **仅会话** | 拒绝 | Key 调用返回 403 `SESSION_REQUIRED`。 |
| `/api/v2/health` | 无需认证 | 无需认证 | 用于版本/能力探测。 |

会话请求若处于“必须改密”（`must_change_password`）状态，除首改密接口外一律 403 `PASSWORD_CHANGE_REQUIRED`。

API Key 支持 `Authorization: Bearer <token>` 或 `X-API-Key: <token>`，两者同时出现时以 `X-API-Key` 为准。

### 2.2 错误信封

所有 JSON 错误统一为：

```json
{ "error": { "code": "INVALID_REALTIME_VIEW", "message": "invalid realtime view", "request_id": "..." } }
```

`request_id` 仅在服务端启用请求 ID 时出现；同一 `code` 同时写入 `X-Error-Code` 响应头。客户端应基于 HTTP 状态 + `code` 分支，不要匹配 `message` 文案。

### 2.3 内容协商与大小限制

- 响应均为 `application/json; charset=utf-8`，SSE 为 `text/event-stream`。
- `/community/sync` 请求体上限 **16 KiB**，`cursor` 长度上限 **128**。
- `/sync/tracks` 请求体上限 **64 KiB**，`ids` 最多 **100** 个且必须唯一。
- 任何通道都不使用 gzip 要求；服务端可能返回 `Cache-Control: no-store`。

### 2.4 能力探测

`GET /api/v2/health` 返回：

```json
{ "status": "ok", "version": "0.21.18", "schema": 9, "revision": 42, "commit": "…", "modified": false }
```

协议协商规则：

- 库同步：显式发送 `protocol=2` 才启用对象增量；不发送即 `1`。不要用 `version` 字符串做精确比较。
- 实时视图：无版本参数；以 `GET /community/events` 是否可用为准。新增的视图字段只能在该服务器版本确认支持后发送，因为服务端**拒绝未知字段**（见 §6）。
- 服务端没有独立的 capability 清单，这是当前协议的已知缺口（§7）；客户端应把“接口 404/400 + 版本”作为降级依据。

## 3. 库同步协议

### 3.1 快照与分页

请求：

```http
GET /api/v2/sync?limit=100&cursor=<opaque>[&protocol=2]
Authorization: Bearer <api-key>
```

| 参数 | 规则 |
| --- | --- |
| `limit` | 1–500；缺省或越界按 **100**。单位是“键”（曲目 + 歌单）。 |
| `cursor` | 空/缺省 = 新快照；否则必须原样回传。 |
| `protocol` | 仅值 `"2"` 启用对象增量；其他值按协议 1。 |

快照键集合：

- 会话身份：所有未删除曲目（含 `missing`），加该用户可见歌单；
- Key 身份：仅 Key 授权歌单内曲目，加这些歌单。

键按字符串排序：`playlist/<id>` 在 `track/<id>` 之前；服务端用“最后一个已发键”作为分页位置。

响应字段（两种协议共有）：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `revision` | int64 | 本次读取的库修订号。 |
| `changed_tracks` | Track[] | 协议 1：本页/本增量的曲目完整对象；协议 2 恒为 `[]`。 |
| `playlists` | Playlist[] | 本页/本增量的歌单完整对象。 |
| `full_snapshot` | bool | 仅快照模式（含最后一页）为 `true`。 |
| `deleted_tracks` | string[] | 增量中已删除/不可见的曲目 ID，升序。 |
| `deleted_playlists` | string[] | 增量中已删除的歌单 ID，升序。 |
| `cursor` | string | 下一游标；总是返回。 |
| `has_more` | bool | 还有下一页/下一批。 |
| `reset` | bool | 客户端必须丢弃旧基线。 |

协议 2 额外字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `object_delta` | true | 固定 `true`，标记对象增量。 |
| `changed_track_ids` | string[] | 需要客户端批量解析的曲目 ID，升序。 |

协议 1 的 `changed_tracks` 与协议 2 的 `changed_track_ids` **互斥**：协议 2 从不返回曲目正文。

快照流程：

1. 空游标请求，得到 `full_snapshot=true`、`reset=true` 与第一页。
2. 记录 `revision`；若分页期间 `revision` 变化，服务端返回 **409 `SYNC_RESTART`**，客户端从头开始。
3. 用返回的 `cursor` 继续，直到 `has_more=false`；此时游标自动进入 `delta` 模式，位置为当前 `revision`。
4. 协议 2 在快照页只拿到 `changed_track_ids`，用 §3.3 批量解析；全部成功后再原子替换本地快照。

### 3.2 增量

携带快照完成后的游标再次请求即进入增量：

- 从持久变更日志读取 `revision > position` 的记录，最多 `limit` 条**变更行**（不是实体数）；可能返回 `has_more=true`。
- 同一实体多次变更合并为最终状态，一条响应内只出现一次。
- 曲目已删除/不存在或不再可见 → `deleted_tracks`；否则 → `changed_tracks`（协议 1）或 `changed_track_ids`（协议 2）。
- 歌单仍可见 → `playlists`；删除 → `deleted_playlists`。
- 没有新变更时 `has_more=false`，游标位置推进到当前 `revision`。

游标失效的判定：

| 条件 | 结果 |
| --- | --- |
| 空游标 | `reset=true`，从头快照。 |
| 签名错误、格式错误、超过 16 KiB | 400 `INVALID_CURSOR`。 |
| 超过 24 小时 | `reset=true`。 |
| 身份/凭证/权限/可见歌单集合变化 | `reset=true`（个别“仅删除本人歌单”的兼容场景由服务端证明后继续增量）。 |
| 增量位置早于日志保留起点，或大于当前 revision | `reset=true`，转为快照。 |
| 快照分页期间 revision 变化 | 409 `SYNC_RESTART`。 |

### 3.3 批量曲目解析（协议 2）

```http
POST /api/v2/sync/tracks
Authorization: Bearer <api-key>
Content-Type: application/json

{ "cursor": "<delta cursor>", "ids": ["t-alpha", "t-beta"] }
```

要求：

- `cursor` 必须是**协议 2 delta 模式**、未处于 `has_more` 分页中（游标内部 `last` 为空）、未过期、绑定匹配、`revision` 等于当前 revision；
- `ids` 1–100 个，符合 `^[A-Za-z0-9_-]{1,128}$`，不得重复；
- 任一 ID 对调用者不可见 → 整个请求 **404 `TRACK_NOT_FOUND`**，客户端不得部分提交。

成功响应：

```json
{ "revision": 13, "tracks": [ { "id": "t-alpha", "title": "Alpha", "...": "..." } ] }
```

顺序与请求 `ids` 一致；`missing`/`removed` 曲目返回不可用投影（标题 `Unavailable`），而不是 404。

错误：

| 状态 | code | 场景 |
| --- | --- | --- |
| 400 | `INVALID_SYNC_BATCH` | 非法 JSON、未知字段、ID 非法/重复、数量越界、游标缺失。 |
| 401 | `AUTH_INVALID` | 认证已变化（Key 撤销、会话失效、auth_version 变化）。 |
| 403 | `SCOPE_DENIED` | Key 没有 `library:read`。 |
| 404 | `TRACK_NOT_FOUND` | 任一 ID 不可见。 |
| 409 | `SYNC_RESTART` | 游标模式/revision/绑定不再匹配。 |

### 3.4 库同步错误表

| 状态 | code | 场景 |
| --- | --- | --- |
| 400 | `INVALID_CURSOR` | 游标解码/签名/模式错误。 |
| 401 | `AUTH_INVALID` | 身份在同步期间失效。 |
| 403 | `SCOPE_DENIED` | Key 缺少 `library:read`。 |
| 403 | `SESSION_REQUIRED` | 管理类接口被 Key 调用（不适用于本协议）。 |
| 409 | `SYNC_RESTART` | 快照分页 revision 变化，或批量解析游标过期。 |
| 429 | `KEY_CONCURRENCY_LIMIT` | Key 并发超限；带 `Retry-After`。 |

## 4. 实时视图协议

### 4.1 视图描述符

`view` 是 JSON 对象，决定观察哪些列表。未知字段直接 400；缺省字段等价于 `false`、空串或 0。

| 字段 | 类型 | 约束 | 作用 |
| --- | --- | --- | --- |
| `catalog` | bool | — | 观察公开目录当前页。 |
| `query` | string | ≤1024 | 目录搜索词。 |
| `offset` | int | 0–1000000 | 目录页偏移。 |
| `subscriptions` | bool | — | 观察本人订阅列表。 |
| `subscription_detail` | string | 空或 ID | 观察某订阅歌单的只读详情。 |
| `subscription_offset` | int | 0–1000000 | 详情偏移。 |
| `subscription_limit` | int | 0–100 | 详情页大小；0 → 50。 |
| `subscription_query` | string | ≤1024 | 详情搜索词。 |
| `invitations` | bool | — | 观察收到的邀请。 |
| `invitation_id` | string | 空或 ID | 只观察该邀请。 |
| `invitation_offset` | int | 0–1000000 | 邀请页偏移。 |
| `owner_playlist` | string | 空或 ID | 观察本人歌单的分享面板。 |
| `owner_offset` | int | 0–1000000 | 分享邀请页偏移。 |
| `public_detail` | string | 空或 ID | 观察公开歌单详情。 |
| `public_offset` | int | 0–1000000 | 公开详情偏移。 |
| `public_limit` | int | 0–100 | 公开详情页大小；0 → 50。 |
| `public_query` | string | ≤1024 | 公开详情搜索词。 |

ID 统一为 `^[A-Za-z0-9_-]{1,128}$`。目录页大小固定 **30**，邀请页固定 **30**。

### 4.2 SSE 唤醒通道

```http
GET /api/v2/community/events?view=%7B%22catalog%22%3Atrue%7D
Cookie: <session>
```

成功响应头：`Content-Type: text/event-stream`、`Cache-Control: no-store`、`X-Accel-Buffering: no`。

`view` 查询参数是 URL 编码后的 JSON，缺省为 `{}`；原始 JSON 长度上限 **4096**，超出或包含未知字段返回 400。SSE 不读取请求体。

帧语法：

```text
event: <name>\n
data: {}\n
\n
```

| 帧 | 触发 | data | 客户端动作 |
| --- | --- | --- | --- |
| `ready` | 连接建立且首个快照已计算 | `{}` | 立即做一次 `community/sync`（空游标）建立基线。 |
| `change` | 提交后合并 150 ms 内的多次提交，**且当前视图快照摘要确实变化** | `{}` | 用保留游标做一次 `community/sync`；不要假设帧里有数据。 |
| `expired` | 会话失效、撤销、改密、凭证/绑定变化 | `{}` | 关闭连接并回到登录；不得自动重连。 |
| `reconnect` | 服务端进入更新维护 | `{}` | 关闭连接，3 秒后重连；重连后重新 `sync`。 |
| `: heartbeat` | 每 15 秒无事件 | 无 | 仅用于保活/超时判定。 |

约束：

- 不支持 `Last-Event-ID`，断线不补发历史帧；恢复一律靠 `community/sync` 的最终状态增量。
- 流建立前可能返回 400 `INVALID_REALTIME_VIEW`、429 `REALTIME_LIMIT`（`Retry-After: 60`）、503 `REALTIME_BUSY`（`Retry-After: 5`）。这些是 JSON 错误，不是 SSE。
- 每用户最多 8 条、全站最多 128 条流；写帧超时 5 秒即断开。
- 心跳间隔 15 秒，客户端读超时应显著大于 15 秒；收到 `expired` 后不要重连。

### 4.3 视图增量同步

```http
POST /api/v2/community/sync
Cookie: <session>
X-CSRF-Token: <csrf>
Content-Type: application/json

{ "cursor": "<opaque or empty>", "view": { "catalog": true, "offset": 0 } }
```

```json
{
  "cursor": "…",
  "reset": false,
  "sections": {
    "catalog": {
      "reset": false,
      "changed": [ { "id": "p-radio", "name": "Radio", "track_count": 13, "...": "..." } ],
      "removed": ["p-old"],
      "order": ["p-radio", "p-new"],
      "meta": { "total": 2, "offset": 0, "limit": 30 }
    }
  }
}
```

响应字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `cursor` | string | 新基线游标；无变化时原样返回请求游标。 |
| `reset` | bool | 服务端丢弃了基线（无/过期/绑定变化/重启）。 |
| `sections` | object | 只有内容发生变化的段才出现；无变化时为 `{}`。 |

段（section）列表与行类型：

| 段 | 何时出现 | `changed` 行类型 | `meta` 固定字段 |
| --- | --- | --- | --- |
| `badge` | 基线必含；仅待处理邀请数变化时进入增量 | 永远为空 | `pending` |
| `catalog` | `view.catalog` | 公开歌单摘要（`PublicPlaylistSummary`） | `total`、`offset`、`limit` |
| `subscriptions` | `view.subscriptions` | 订阅歌单视图（`Playlist`） | `{}` |
| `invitations` | `view.invitations` | `PlaylistInvitation` | `total`、`offset`、`limit` |
| `subscription_tracks` | `view.subscription_detail` | 曲目浏览行（`Track` 去歌词 + `detail_loaded`） | `total`、`offset`、`limit`、`playlist`；不可见时 `{}` |
| `owner_playlist` | `view.owner_playlist` | `Playlist` | `available` |
| `owner_invitations` | 同上 | `PlaylistInvitation` | `total`、`offset`、`limit` |
| `detail_playlist` | `view.public_detail` | `Playlist` | `available` |
| `detail_tracks` | 同上 | 曲目浏览行 | `total`、`offset`、`limit`；不可见时 `{}` |

段内语义：

- `changed`：只包含行指纹变化（或 `reset` 时全部）的行，顺序与 `order` 中对应项一致。
- `removed`：相对上一基线的 ID，升序；只用于删除，不会与 `changed` 重复。
- `order`：该段**完整的新顺序**，客户端应整体替换顺序，而不是只重排 `changed`。
- `meta`：完整替换；不支持部分更新。
- 段缺席 = 该段未变化；不得据此清空该段。
- `delta.reset=true`：该段以本次 `changed` 为全量重建；`removed` 为空。
- 单段行数超过 **5000**：该段进入 overflow。当前快照 overflow 时 `changed` 为该段全量；上一基线 overflow 时 `delta.reset=true`。两种情况下客户端都应按全量重建该段，根 `reset` 仍为 `false`。
- 根 `reset=true`：所有段基线失效；客户端应清空该视图缓存，凡响应出现的段都按全量处理。
- 根 `reset=false` 且 `sections={}`：无变化；继续用原游标。

游标与容量：

| 项 | 值 |
| --- | --- |
| 游标形态 | 24 字节随机数的十六进制串（48 字符），服务端内存映射，**不可解析**。 |
| TTL | 5 分钟；无变化重取时滑动续期，内容变化即换新游标。过期即 `reset=true`。 |
| 容量 | 全服务端最多 64 条基线，按最早过期淘汰。 |
| 绑定 | 用户 ID + 凭证 ID + 认证版本 + 视图参数；任一变化即 reset。 |
| 多实例 | 基线在进程内存；多实例/重启后必须容忍 reset（不要做 sticky 假设）。 |

快照计算有 **5 秒** 读超时；超时或内部容量不足返回 503 `REALTIME_BUSY`（`Retry-After: 5`），不会返回半截结果。

| 状态 | code | 场景 |
| --- | --- | --- |
| 400 | `INVALID_REALTIME_VIEW` | JSON 非法、未知字段、字段越界、`cursor` 超 128 字符、body 超 16 KiB。 |

## 5. 客户端状态机

### 5.1 库同步

```text
无基线 ──空游标──> 快照分页 ──has_more=false──> 增量
   ^                    │ 409 SYNC_RESTART        │
   └────────────────────┴─────────────────────────┘
增量 ──reset=true──> 丢弃基线，回到“无基线”
增量 ──protocol=2 且 changed_track_ids 非空──> 批量解析 ──成功──> 原子提交 ──> 增量
```

规则：

- 只有完整快照 + 全部批量解析成功后才提交本地库；任一步失败保留旧快照。
- `409 SYNC_RESTART` 不是错误重试：从空游标重新快照。
- 增量提交前校验 `revision` 单调；不要用 `revision` 做本地主键。
- 快照分页期间不要并发写本地库。

### 5.2 实时视图

参考实现（网页端）行为：

1. 视图变化（路由/页签/搜索/分页）→ 关闭旧 SSE，记录新 `view`，清空该视图缓存，建立新连接。
2. 收到 `ready`/`change` → 100 ms 去抖后 `POST community/sync`。
3. 每个视图缓存最多 10 份“游标 + 段基线”；`reset=true` 清空对应缓存。
4. `expired` → 登出；`reconnect` → 3 秒后重连；网络错误 → 关闭并在 60 秒兜底轮询时补取。
5. 429/503 按 `Retry-After` 退避，避免风暴。
6. 页面隐藏时断开；恢复可见时重连并补取。
7. 应用段：先 `removed`，再 `changed`，再整体替换 `order`/`meta`；`reset` 段先清空。

## 6. 兼容性规则

1. **游标不透明**：不得解析、比较或构造；只存字符串并回传。
2. **服务端拒绝未知请求字段**（实时 `view`、`community/sync` 顶层、`sync/tracks`）。客户端只能在确认服务器支持后发送新增字段；这意味着新增视图字段对旧服务器是破坏性的，必须按版本门控。
3. **响应可加字段**：客户端必须忽略未知 JSON 字段和未知段名；不能因多一个字段而报错。
4. **段名可加**：新增段对旧客户端应可忽略；删除/重命名段属于主版本变化。
5. **错误码可加**：按状态码 + 已知 code 分支，未知 code 走通用错误 UI。
6. **SSE 帧名可加**：未知 `event` 应忽略而非断开；`data` 目前恒为 `{}`，未来可能携带提示但客户端仍应以 `sync` 结果为准。
7. **协议 2 协商**：只有客户端显式发送 `protocol=2` 才启用；服务端不得对未声明的客户端返回对象增量。
8. **超时与容量**：5 秒快照、64 条实时基线、8/128 条 SSE 是当前实现上限；客户端必须把 reset 当正常路径而不是异常。

已识别的协议级缺口（不阻塞本次交付，记录待办）：

1. 无 capability 清单/协商端点；实时视图新增字段只能靠版本文档门控。
2. 实时游标是单进程内存，多实例部署必须容忍全量 reset；未提供共享游标存储。
3. SSE 的 `change` 不带修订号，无法判断是否值得 `sync`；当前按 100 ms 去抖合并。

5. 库同步无 ETag/条件请求；大库分页依赖 revision 重启。
6. 上传续传、标签同步等通道尚无同等契约文档。

## 8. 可执行契约

目录：

```text
contracts/
├── schemas/                  # JSON Schema 2020-12（子集）
├── examples/                 # 请求/响应/SSE 帧样例
├── fixtures/mock-state.json  # mock 固定数据
├── lib/validate.mjs          # 零依赖 schema 校验器
├── lib/sse.mjs               # SSE 帧解析/序列化
├── mock-server.mjs           # 参考 mock（Node，零依赖）
├── verify.mjs                # 样例 + mock 端到端自检
└── README.md
```

命令：

```bash
node contracts/verify.mjs                 # 样例 + mock 端到端逐项契约检查
node contracts/mock-server.mjs --port 8787
go test ./server/internal/music -run TestProtocolContract -count=1
```

mock 约定（仅测试用，不属于生产协议）：

| 项 | 值 |
| --- | --- |
| 库同步认证 | `Authorization: Bearer mock-key` 或 `X-API-Key: mock-key` |
| 实时认证 | `Cookie: session=mock-session`，POST 另加 `X-CSRF-Token: mock-csrf` |
| 控制端点 | `POST /__mock/commit`、`/__mock/expire-cursors`、`/__mock/expire-auth`、`/__mock/reconnect`、`GET /__mock/state` |
| 心跳 | `MOCK_HEARTBEAT_MS`（默认 15000） |

约束与实现的关系：

- `examples/*.json` 由 Go 测试 `protocol_contract_test.go` 以 `DisallowUnknownFields` 解码到真实类型，JSON tag 改名会立刻失败。
- `verify.mjs` 用同一份 schema 校验样例和 mock 实际响应，防止“文档示例能跑、mock 不能跑”。
- schema 只使用校验器支持的子集；新增关键字需同时扩展 `lib/validate.mjs`，否则自检会报 unsupported keyword。
