# 共同打标与便捷标签器开发计划

日期：2026-10-29。用户确认按 Eagle 风格参考实现便捷标签器，并开放普通用户参与全站公共整理。本轮只本地开发及提交，不推送、不发布、不操作云端。使用编写计划、执行计划及子代理开发技能，将后端权限与新标签器界面分开实施并集中验收。

## 范围与交互

普通用户可为全站可见曲目添加／移除公共标签，创建公共词条；公共词条重命名、别名维护、合并、删除以及分组管理仍归管理员。个人标签仅本人可见，不扩大 Key 权限。已有 schema 8 数据原样保留。

右侧非模态标签器打开时曲目列表仍可选择、搜索及翻页，自动让出空间；显示当前选择，支持固定对象，未固定时跟随选择。外侧空白关闭，固定后保留。上传草稿及大规模全部匹配结果继续走明确保存／任务确认，不冒充即时原子操作。

名称与别名优先复用，按完全匹配、前缀、包含排序；别名命中显示标准名及匹配信息，不推断未知同义词。分组／公共个人作用域始终明确。方向键选项、Enter 选择；无匹配时 Enter 创建并添加。有相似结果时创建须明确选取创建行。请求未完成、失败或输入法确认期间禁止创建；同名并发冲突重新搜索复用。

单曲和小范围点击即保存；部分拥有点击补齐，全有移除使用明确按钮。操作冻结当时目标及版本；结果可撤销，撤销只还原本次真正变化且拒绝覆盖后续修改。大集合保留原有批量任务。显示当前已有、最近使用标签，最近使用按账户隔离并有界保存。

## 阶段

追加需求：曲库常用筛选增加“未标签”，默认没有公共标签；使用现有 `untagged_public` 服务端查询、计数、分页和 URL 恢复，可叠加其他条件。未标个人标签仍通过高级筛选选择。

- [x] T01：开放公共打标／词条创建权限，保持管理权限边界；完善搜索排序及并发去重契约，覆盖单曲、批量、上传去重和隐私回归。
- [ ] T02：新增非模态标签器及布局，曲目选择联动／固定、分组／作用域、别名搜索、键盘创建、最近使用；上传及大范围保留原任务入口。
- [ ] T03：小范围即时保存及安全撤销，冻结目标、版本冲突处理、失败提示和迟到响应保护；网页键盘、触屏、窄屏及列表操作联调。
- [ ] T04：专项验证、CI 接入、更新权限文档和验收记录，创建本地提交。完整远程 CI 留待用户授权推送。

## 文件与验证

后端：`server/internal/music/tag_dictionary.go`、`track_tag_links.go`、`tag_batch.go` 及相邻 Go 测试。前端：新增 `tagger-ui.js/.css`，接入 `tag-editor.js`、`library.js`／`browse-ui.js` 选择入口，`index.html` 与 `server.go` 资源声明。验证脚本在 `server/tests`，通过现有 Actions 网页套件执行。

验证先覆盖旧权限失败、搜索别名、重复创建与撤销冲突，再做真实浏览器非模态选择、点击不误关、Enter／中文输入法、范围变化、公共个人隔离和小屏。每项仅在对应验收通过后勾选；不改 schema，不迁移或清理用户数据。
