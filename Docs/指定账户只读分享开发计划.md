# 指定账户只读分享开发计划

日期：2026-10-23。公开订阅第二期，用户已明确选择只读分享，协作编辑后续实施。

## 范围与行为

新增 `shared`（仅分享）可见性，与 private／public 并列。仅分享不进入公开目录，也不能仅凭 URL 获得访问。所有者输入完整账户名发出站内邀请，不向普通用户提供账户列表、前缀搜索、邮箱或外部消息发送。

邀请绑定目标账户 ID 和当时所有者，状态为 pending／accepted／declined／revoked。被邀请者登录并完成首次改密后，可以接受或拒绝；接受与建立订阅在同一事务完成，不自动授权任何 Key。待处理邀请不自动到期，作者可撤回；再次邀请必须显式操作并检查邀请版本。

邀请接受后，源 UUID、只读内容跟随、个人备注隔离及显式 Key 勾选沿用第一期。仅所有者管理邀请，管理员需要先接管才可代表新所有者分享。分享不会授予编辑源歌单、删除曲目、再次邀请或转移所有权的权限。

可见性规则：私有时暂停全部外部歌单访问；公开时保留第一期规则；仅分享时只有已接受当前所有者邀请的账户可访问。原公开订阅者不能因模式切换自动获得定向授权。已接受的邀请在转私有或作者停用期间保留，恢复仅分享／启用后可恢复；撤回后保留最小失效订阅和已配置 Key，重新邀请须对方再次接受才能恢复。

取消订阅清除订阅、个人备注及相关 Key 授权；已接受的邀请仍保留，接收者可从邀请页重新订阅，但需重新勾选 Key。源删除清除邀请，已有订阅保留最小 deleted 项。管理员接管强制私有并撤销全部旧邀请，新所有者必须重新邀请。其他有效歌单／全局曲库授权独立；已有下载字节不能收回。

## 数据和接口

版本 0.13.0，SQLite schema 7，仍使用 `/api/v2`。增加有外键的 `playlist_invitations` 表：随机 UUID、playlist_id、inviter_id、recipient_id、state、version、已分享名称快照及创建／更新时间；每歌单每目标账户唯一。歌单 visibility 约束增加 shared。每个歌单至多 100 条邀请，列表分页读取，每页默认 30，最多 100。

沿用开发阶段不迁移约定：schema 6 及更早版本拒绝打开并保持字节不变。部署前停止核对过路径的旧实例，将测试数据隔离至 build/.server-archive，初始化全新库，admin 密码由用户在终端设置；不读取或代填密码。隔离测试只使用自行生成的账户、媒体与数据库。

接口均需账户会话，写请求需 CSRF；Key 不可管理或接受邀请：

| 方法 | 路径 | 条件 |
| --- | --- | --- |
| GET | `/playlists/{id}/invitations?offset=0&limit=30` | 仅所有者查看自己歌单的邀请 |
| POST | `/playlists/{id}/invitations` | 完整 username；If-Match 为歌单版本；重复待处理／已接受不产生副作用 |
| DELETE | `/playlists/{id}/invitations/{inviteID}` | 撤回，If-Match 为邀请版本 |
| POST | `/playlists/{id}/invitations/{inviteID}/resend` | 显式重新邀请，If-Match 为邀请版本 |
| GET | `/invitations?offset=0&limit=30` | 仅本人收到的邀请，不包含源曲目、封面或作者备注 |
| POST | `/invitations/{inviteID}/accept` 或 `/decline` | 仅目标账户，If-Match 为邀请版本；必须仍匹配当前所有者、仅分享模式及启用状态 |

无权访问统一 404；缺版本 428，旧版本及已结束状态冲突 409；非法账户／状态 400，不区分账户不存在和停用。列表 `Cache-Control: no-store`。邀请 URL 为 `/#/invitations/{inviteID}`，不是凭证，转发后其他账户也不能访问或接受。

统一有效性 helper 覆盖详情、封面、Key 授权、媒体及同步，新增 `share_revoked` 失效原因。权限变化触发同步 reset。邀请接受／撤回／拒绝／重新邀请、自动订阅、接管失效与审计必须事务一致，失败不留部分授权。

## 页面与客户端

“我的歌单”增加“分享邀请”页签，不增加侧栏入口。收到的邀请显示已分享名称、作者、状态和接受／拒绝；已接受可进入订阅或重新订阅。支持分页、分享链接登录目标恢复与手机布局，仅相关页面可见时按五分钟间隔刷新，也提供手动刷新。

本人歌单详情增加“分享设置”，以独立弹窗展示邀请列表、输入完整账户名、新邀请、撤回及再次邀请；可见性仍在独立编辑页保存，非 shared 时解释需要先改为仅分享。链接复制提供自动消失提示，无确认框。退出清理邀请列表及弹窗，不能留下上一账户数据。

MusicPlayer2 增加 shared 状态与 `share_revoked` 原因文案，已知失效后的播放、离线保存及最近入口处理沿用第一期；接受分享后手动选择 Key 授权。客户端源码与测试在独立仓库本地提交，测试继续置于 test-results，固定生成 build/MusicPlayer2.exe 与 dist/MusicPlayer2.zip。
