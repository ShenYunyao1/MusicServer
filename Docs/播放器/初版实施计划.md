# 初版实施计划

范围：服务端和 MusicPlayer2 Windows 客户端。ESP32 暂缓。

## 本版验收

- Go 服务端运行于本地，扫描指定媒体目录，关联同名歌词，查询和管理歌单及注释。
- 提供简单 Web 管理入口，支持上传、修改曲目信息和歌词、删除库记录。
- MusicPlayer2 设置页保存服务器地址和凭据，媒体库增加服务器选项卡，显示歌单和曲目。
- 网络请求在后台执行；播放时完整下载曲目并验证 SHA-256，再交给现有本地播放内核。
- 支持手动刷新、离线保存和断网读取已保存的歌单与缓存。

## 文件职责与顺序

1. `server/internal/music/{types,store,server}.go`：数据、持久化、扫描、HTTP 接口及 Range 下载。
2. `server/internal/music/index.html`：无需前端构建的管理页；`server/cmd/musicserver/main.go`：命令行入口。
3. `MusicPlayer2/MusicPlayer2/RemoteLibraryClient.{h,cpp}`：认证请求、曲目与歌单读取、流式缓存下载。
4. `MusicPlayer2/MusicPlayer2/RemoteLibraryConfig.{h,cpp}`：独立配置文件、Windows DPAPI 保护凭据、缓存命名空间。
5. `MusicPlayer2/MusicPlayer2/ServerSettingsDlg.*`、`ServerLibraryDlg.*`、`RemoteLibrary.rc`：设置和浏览子页，后台任务，复用 `CPlayer`。
6. 修改 `OptionsDlg`、`CMediaLibDlg` 和工程注册文件，构建并联调。

## 技术边界

- 第一版使用原子替换的 JSON 文件持久化，暂不引入数据库驱动。协议与存储实现分离，后续迁移 SQLite。
- `sync` 第一版是修订号检查和完整快照返回；不能当成逐项增量日志。桌面页先手动刷新。
- 首次播放完整下载后开始播放；逐段边播边缓存、Range 续传、LRU 容量控制留待后续。
- 自有 API 优先打通客户端；本版不宣称兼容 OpenSubsonic。
- 本机曲目测试仅扫描和下载读取，不删除或改写原始音乐文件。写入功能使用测试目录。
- 保留上游启动空歌单 Debug 断言作为已知问题；联调使用有效本地音频启动。

## 验证

- Go：`go test ./...`、`go vet ./...`、构建服务端，真实目录扫描和 Range 请求。
- C++：MFC Debug x64 编译；使用隔离便携配置启动，实际打开服务器页、下载曲目、验证文件哈希和断网缓存。
- 不把构建成功视为播放和所有界面行为均已验证。
