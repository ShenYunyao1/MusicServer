# 多用户版本开发方案与进度

日期：2026-10-22。状态：F01–F10 接口功能已验证，其余功能按清单实施，完整页面与发布验收尚未完成。

本文是本期多用户开发的执行依据。此前《账号登录与多账户、歌单分享方案》保留为阶段记录；其中“成员默认不能浏览全库、不能上传”等旧设想，由本文确认的全局曲库规则替代。

## 一、目标与范围

本期采用“全局曲库＋私人歌单＋资源归属”，沿用 Go、SQLite、服务端会话和播放器 API Key。用户由管理员创建，不开放自助注册。

实现管理员创建账户、独立临时密码、首次登录强制改密、账户停用与重新启用、成员浏览全局曲库、个人歌单、曲目上传与归属、受引用保护的软删除，以及管理员按账户查阅和接管资源。

本期不实现歌单分享、公开链接、邮件通知、第三方登录、账号永久删除、普通用户物理删除音频或旧数据库格式迁移。不修改独立的 `MusicPlayer2/` 客户端仓库。

拟定发布版本为 `0.10.0`，SQLite schema 为 `5`，API 继续使用 `/api/v2`。数据库格式不兼容时，使用新的测试库重新初始化，不提供旧库转换或兼容路由。

## 二、已确认的产品规则

### 账户与密码

- 管理员指定登录名创建普通成员；内部归属始终使用账户 UUID。
- 登录名沿用当前规则：3–64 个 ASCII 字母、数字、点、短横线或下划线，首字符为字母或数字，忽略大小写；中文可用作显示名。
- 系统为每个新账户生成独立、不可预测的临时密码，创建成功后只展示一次。数据库只保存密码哈希，不在日志、审计或列表中返回明文。
- 本机首次初始化管理员仍由操作者输入密码，不自动生成临时密码，也不额外要求再次修改该初始化密码。
- 首次登录必须修改密码。完成前仅可读取本人的必要身份信息、修改密码、退出和进行必要的会话活动更新；不能浏览曲库、上传、管理歌单或使用 Key。
- 用户可自行修改密码。管理员只能重置密码，不能读取原密码；重置生成新的独立临时密码，并再次要求首次改密。
- 管理员重置撤销旧会话，并提供“同时撤销该账户所有 Key”的明确选项；普通用户自行改密保持现有 Key 策略。
- 本期新增账户默认是普通成员；不提供通过普通账户创建请求附带角色字段来提升权限的入口。

### 停用、重新启用与接管

会话是浏览器登录后建立的登录状态：浏览器保存会话 Cookie，服务端校验其对应的账户、有效期和撤销状态，从而免去每次请求都输入密码。播放器 API Key 是独立凭证，其停用和恢复不需要恢复浏览器会话。

- 停用账户时立即撤销浏览器会话，并通过账户启用状态阻止其全部 API Key 使用；不撤销或删除 Key，不修改密钥、原有授权或到期时间，不删除调用统计。全局曲库中的曲目继续可用，私人歌单仍保留。
- 账户可以重新启用。原有 Key 在未单独撤销、未过期且满足当前权限和首次改密要求时，恢复使用同一密钥，调用统计继续累计；浏览器旧会话不恢复，用户需要重新登录。原有强制改密状态继续有效。
- “账户停用导致暂不可用”和“主动撤销 Key”是两种状态。被单独撤销或已过期的 Key 不会因为账户重新启用而恢复；停用期间到期的 Key 也不会被延长有效期。
- 单纯停用或启用不改变资源所有权。
- 资源接管是独立的管理员操作，可以将停用账户的指定曲目、指定歌单或全部资源转给一个已启用的账户，包括管理员本人。
- 接管后重新启用原账户，不自动把资源转回；若需转回，管理员显式转移并记录审计。
- Key 和登录会话不随资源转移。不能停用最后一个有效管理员；重复停用、重复启用和并发修改都需要一致的状态及版本检查。

### 全局曲库与私人歌单

- 所有已登录、已启用且完成首次改密的用户，可以浏览、搜索和播放全局曲库，并将曲目加入自己的歌单。
- 用户歌单仅本人和管理员可见；不向其他成员暴露歌单名称、备注、排序、内容或存在性。
- 成员可以编辑自己的歌单、成员顺序和个人备注。个人操作不修改全局曲目信息或其他人的排序。
- 系统 `library` 表示全局曲库，不属于任何个人，不参与个人歌单的接管和私人引用统计。
- 曲目缺失或被软删除后，已有歌单保留成员 UUID、顺序和个人备注，并显示最小的“不可用”占位；恢复后能重新播放。

### 曲目归属、上传和删除

- 曲目 UUID 继续是永久主键。`uploaded_by` 记录原始上传者，`owner_id` 记录当前管理者；转移管理权不改写原始来源。
- 普通用户可上传曲目，新增曲目进入全局曲库；只有当前管理者和管理员可修改其全局元数据。
- 歌单引用不授予曲目管理权。其他用户上传命中相同内容时，复用已有曲目并明确提示，不改变 UUID、原始上传者或管理者，也不覆盖已有元数据。
- 服务器目录扫描首次发现的曲目默认归负责扫描的管理员；后台自动扫描使用明确记录的管理员归属，不能让扫描随机选择或更改现有所有者。
- 普通用户删除本人管理的曲目前，检查是否仍被其他用户歌单引用。存在引用时拒绝，交由管理员处理；停用账户的私人歌单引用也计入保护，系统 `library` 不计入。
- 管理员可以强制软删除曲目。软删除保留原文件和歌单关联，普通用户不能直接物理清理文件。
- 引用检查、软删除、版本更新、增量日志和审计必须处于同一事务，避免与其他用户同时加入歌单时产生越权删除或引用丢失。
- 管理员可恢复软删除曲目；恢复保留原 UUID 和归属。成员不能通过重新上传相同文件绕过已下架状态；已下架的重复内容应提示联系管理员处理。

### API Key、统计与管理员查阅

- 每个用户管理自己的播放器 Key。Key 只能访问其所属启用账户拥有的权限与显式授权范围的交集，不具备上传或管理能力。
- 成员浏览全局曲库，不等于其每个 Key 自动开放全库。创建 Key 时默认只授予本人选定的歌单；全库读取必须显式选择系统 `library`。
- Key 不能授权其他用户的私人歌单；管理员访问他人歌单的管理权限也不能直接透传给播放器 Key。
- 成员只查看自己的 Key 统计；管理员可以按账户查阅。新增零统计、改名同步、撤销删除统计的现有规则继续保留，汇总与列表范围一致。
- 账户停用期间保留其 Key 和累计统计，页面标明“账户已停用”；重新启用后在同一条记录上继续累计。统计保留不赋予该账户访问接口的权限；主动撤销 Key 才删除相应统计。
- 管理后台按账户分别展示“当前管理的曲目”“原始上传曲目”“拥有的私人歌单”。歌单引用的曲目不自动归该账户所有。
- 管理员查阅私人资源、修改账户、重置密码、停用/启用和接管资源均记录操作人和目标；不在审计中记录密码、令牌或完整 Key。

数据模型要点：

- `users` 增加 `must_change_password` 等状态；账户启停和密码变更继续更新相应版本并撤销旧会话。Key 认证逐次检查所属账户状态，账户启停不修改 Key 的撤销状态；显式撤销和重置密码时选择的撤销操作独立处理。
- `tracks` 增加 `uploaded_by`、`owner_id`，SQL 字段与返回对象保持一致；索引支持按账户筛选和引用检查。
- 用户歌单已有 `owner_id`，成员顺序和歌单显示排序均需限制在所属账户内；管理员查阅他人歌单不会改变自身或对方排序。
- 新增用户时不复制音频、不复制全局曲目；去重只复用资源，不授予管理权。
- 暂存对象继续关联用户，查询、封面、提交、取消都检查其所属账户；客户端提交的 `owner_id`、`uploaded_by`、`user_id` 不能替代后端身份。
- 本期将默认数据库名统一为固定的 `build/data/library.sqlite`，schema 版本存入数据库内部，后续不再靠文件名区分格式。同步更新默认值、CLI、测试和文档；不回退查找 `library-v4.sqlite`，不自动导入旧测试库。
- 程序仍固定为 `build/musicserver.exe`；Linux 产物和发布包保持现有规范，全部运行数据仍在 Git 忽略的 `build/` 下。

## 四、接口草案

路径前缀均为 `/api/v2`，实际响应 DTO 随对应功能测试一起确定。

| 方法与路径 | 作用与访问边界 |
| --- | --- |
| `GET /admin/users` | 管理员列表、启用状态与必要计数 |
| `POST /admin/users` | 管理员指定登录名创建成员，成功响应一次性返回临时密码 |
| `POST /admin/users/{id}/reset-password` | 管理员重置为新临时密码，支持显式撤销 Key |
| `PATCH /admin/users/{id}` | 管理员修改显示名和启用状态，必须提供当前版本 |
| `GET /admin/users/{id}/tracks?relation=owned\|uploaded` | 区分当前管理与历史上传资源，支持分页 |
| `GET /admin/users/{id}/playlists` | 管理员查阅目标账户的私人歌单 |
| `POST /admin/users/{id}/transfer` | 转移停用账户指定资源或全部资源到已启用账户 |
| `GET /auth/me`、`PUT /auth/password` | 返回强制改密状态、本人改密；首次改密成功后重新登录 |
| `GET/POST/PATCH/DELETE /auth/keys...` | 调整为本人 Key 管理；不得猜 ID 管理他人 Key |
| `GET /auth/keys/stats` | 本人 Key 统计 |
| `GET /admin/stats?user_id=...` | 管理员全局或按用户统计 |
| 现有曲目、媒体、封面、歌单、上传及同步接口 | 保留路径，调整到统一的全局曲库和对象所有权授权 |

已有资源写入继续使用 `If-Match`；版本变化返回 `409 VERSION_CONFLICT`，缺少版本返回 `428 VERSION_REQUIRED`。引用保护拒绝返回 `409 TRACK_IN_USE`，不泄露引用者的私人歌单名称或备注。对无权查看的私人对象返回 404。首次改密限制使用稳定错误码，前端据此进入改密流程。

接管请求需明确源账户、目标账户、资源选择和读到的版本；整账户批量操作必须验证源账户仍处于停用状态、目标仍启用，以及资源没有被并发改归他人，冲突时整体回滚。

## 六、验证方法与完成标准

在 `server` 目录使用当前可用的 Go 1.26+ 工具链。行为改动先建立失败回归，再实现；数据库写入需覆盖权限拒绝、事务回滚和并发冲突。文档及机械路径调整不要求新增镜像实现的测试。

目标验证命令：

```powershell
go test ./internal/music -run 'TestUsers|TestMultiuser|TestTrackLifecycle' -count=1
go test ./... -count=1 -timeout 120s
go vet ./...
go test -race ./... -count=1 -timeout 180s
```

定向测试名称可随新增文件确定，以实际执行记录为准。Race 检查需要可用的 C 工具链；当前本机已有 Qt MinGW 13.1，不依赖系统旧版 MinGW。Linux 交叉编译通过不能替代 Linux 主机实际运行验证，未运行时必须明确记录。

Windows 脚本入口保持不变，构建前停服：

```bat
cd server
call build.bat
call start.bat
```

BAT 默认暂停；自动化调用显式设置 `MUSIC_SERVER_NO_PAUSE=1`。发布包使用 `package-release.ps1` 复用统一构建入口。运行目录与暂停行为继续通过以下回归，上传浏览器测试仍依赖可用的 ffprobe：

```powershell
python tests/runtime-layout.py
python tests/bat-pause.py
node tests/management-ui.cjs
```

浏览器回归要使用临时数据库、媒体和自建进程，不把测试账户/密码注入当前运行实例。新增场景必须覆盖管理员创建 A/B、各自首次改密、A 上传 B 收藏、B 删除被拒、A 删除因 B 引用被拒、管理员下架与恢复、停用 A 后 B 继续播放、接管 A 的资源、重新启用 A 后归属保持接管结果，以及 A/B 的 Key 和统计互不串用。

启停场景还必须验证：停用前 A 的 Key 可用且已有统计；停用后该 Key 请求被拒，统计保持原值；重新启用后使用同一密钥继续调用并累计。另分别覆盖旧浏览器会话失效、已主动撤销的 Key 不恢复、停用期间已过期的 Key 不恢复，以及已接管的私人歌单不因原账户恢复而重新授权。
