# 服务器前端布局重构计划与进度

日期：2026-10-23。状态：P01–P11 已实现并完成对应验收。实施基线为 0.10.0，参考提交 `73cd764`；本次发布版本为 0.10.1。

本文记录前端功能分布、页面布局、交互逻辑及分阶段验收进度。最初仅创建计划，后续按用户授权分阶段实施，详见执行记录。

## 一、目标与边界

围绕“全局曲库＋私人歌单＋资源归属”，将现有界面整理为音乐使用、播放器接入、系统管理三个区域。普通用户能直接找到浏览、播放、收藏、上传和播放器配置；管理员能明确区分本人资源与他人资源、日常操作与系统维护。

账户、权限、数据归属、Key 生命周期与接管规则继续以[多用户版本开发方案与进度](多用户版本开发方案与进度.md)为准。本文只规划前端组织和交互，不重新定义这些业务规则。

范围与限制：

- 保留现有 Go 内嵌静态页面、SQLite 和 `/api/v2`，不因布局调整引入前端框架、外部 CDN 或额外部署服务。
- 不实施共享歌单、公开链接、自助注册、账户永久删除、物理清理音频和旧数据库兼容。
- 不修改独立的 `MusicPlayer2/` 客户端仓库。
- 不默认扩大播放器 Key 授权，不将管理员查阅权限传递给 Key。
- 网页播放定位为曲目预览，不扩展为完整播放器或新增播放队列协议。
- 新增后端接口仅限页面验收确有必要的缺口，实施前补充具体接口、权限及验证范围；不假设前端已有全站私人引用等数据。
- 编译和运行仍遵循[服务器编译与运行目录规范](服务器编译与运行目录规范.md)，源码、测试数据及发布产物不混放。

## 二、现状与问题

本次依据 `index.html`、`account.js`、`users.js` 和已有浏览器测试检查功能；未登录或修改正在运行服务中的用户账户，不将源码检查等同于全部账户页面的实机验收。

| 当前分布 | 问题 | 规划处理 |
| --- | --- | --- |
| 概览放置统计、API 测试、扫描、恢复、审计和备份 | 日常使用与维护混杂，结果区域互相覆盖 | 概览只保留摘要，维护功能移入对应页面 |
| 部分导航按角色改名，页面标题保留原名 | 全局曲库、曲目管理等叫法不一致 | 统一导航、标题、面包屑与操作名称 |
| 曲目列表集中展示所属歌单、歌词和音频参数 | 表格过宽，重点不清晰 | 默认展示核心列，详细信息移至详情侧栏 |
| 播放、编辑、加入歌单等依赖右键 | 入口难发现，手机操作困难 | 提供行操作和选择后的批量工具栏，保留右键快捷方式 |
| 用户资源追加在账户列表下方 | 页面过长，所属账户不够醒目 | 用户列表进入独立用户详情 |
| 上传队列展开大量表单 | 批量任务状态不易判断 | 默认紧凑列表，按需展开元数据和附件 |
| 操作反馈主要写入同一顶部状态栏 | 容易覆盖，与操作位置分离 | 区分局部反馈、全局通知及持续任务状态 |
| 页面和详情主要记录在内存状态中 | 刷新、返回、直达详情体验不完整 | 增加可定位的页面地址与恢复逻辑 |
| 普通用户只能读取自己的私人歌单 | 无法推断曲目的全站引用状态 | “孤立曲目”改为“未加入我的歌单”，禁止据此推断他人收藏 |

## 三、导航与公共布局

```text
音乐
  全局曲库
  我的歌单
  上传任务

播放器
  播放器接入

管理（仅管理员）
  管理概览
  用户管理
  曲库维护
  系统设置
```

- 普通用户默认进入全局曲库，管理员默认进入管理概览。已登录后刷新有效页面时保留当前位置，不强制跳回首页。
- 管理员的“我的歌单”和“播放器接入”始终表示本人；他人资源通过用户管理查阅，并持续显示所属账户。
- 顶栏显示页面标题或面包屑，以及账户菜单。账户菜单收纳修改密码、登录会话、退出登录，显示当前角色。
- 页面标题区保留一个主要操作，次要操作放在旁边或更多菜单。搜索和筛选放在对应列表上方，不增加含义不明的全局搜索框。
- 桌面端使用分组侧栏，手机端使用可展开的导航抽屉。移动端不依赖悬停、右键或拖拽才能完成操作。
- 曲目预览固定在底部，显示当前曲目、暂停和关闭；预留内容底部空间，不遮挡表单及分页。
- 登录、首次强制改密保持独立阻断页面，完成前不能进入业务布局。

地址建议使用 hash 路由，避免新增服务端页面路由要求：

| 地址示例 | 用途 |
| --- | --- |
| `#/library` | 全局曲库，筛选和搜索参数可随地址记录 |
| `#/playlists`、`#/playlists/<id>` | 本人歌单列表及详情 |
| `#/uploads` | 上传任务 |
| `#/player/keys`、`#/player/stats` | 本人 Key 与统计 |
| `#/admin/overview` | 管理概览 |
| `#/admin/users`、`#/admin/users/<id>` | 用户列表及指定用户详情 |
| `#/admin/library/<tab>` | 扫描、文件缺失、已下架曲目 |
| `#/admin/settings/<tab>` | 常规、备份、更新、操作记录 |

路由参数不能携带密码、完整 Key 或会话令牌。无权限地址返回可理解的页面提示并提供返回入口；对象不存在或不可访问时沿用后端的统一可见性规则。

## 四、页面功能与元素分布

### 1. 全局曲库

从上到下依次为标题与上传入口、搜索与筛选、选择后的批量工具栏、曲目列表、列表计数或分页控制。

- 常用筛选：全部曲目、我的上传、我管理的曲目、未加入我的歌单。
- 默认列表：选择框、封面与标题、歌手、专辑、可用状态、操作。
- 行操作提供播放、加入歌单和更多菜单；右键与行菜单使用相同权限判断。
- 选中后展示已选数量、加入歌单、取消选择；删除类批量操作仅对有管理权的选中曲目开放。
- 曲目详情侧栏展示歌词、音频参数、风格、全局备注、管理者和来源等当前身份有权读取的信息；UUID 等技术字段置于次要信息区。
- 修改全局元数据或附件限当前管理者和管理员；个人歌单备注不得误写入全局备注。
- 普通用户不展示服务器文件路径或其他用户私人歌单名称。未加入我的歌单不等于无人引用，也不构成可删除依据。
- 不将全量数据伪装成服务端分页；若确需列表接口分页，在计划中补充搜索、排序、选择范围和权限的接口验收。

### 2. 我的歌单

- 列表展示封面、名称、描述摘要、曲目数和操作入口，提供搜索、新建和排序。
- 点击进入独立详情：面包屑、歌单信息、添加曲目、编辑信息、更多操作、曲目列表。
- 详情列表提供播放、个人备注、移出歌单、调整顺序；手机端补充非拖拽排序方式。
- “移出歌单”只删除本歌单引用；“删除曲目／下架曲目”明确影响全局曲库，不混用按钮文案。
- 缺失或下架曲目保留 UUID、顺序和个人备注的不可用占位，不自动移出歌单。
- 系统 `library` 通过全局曲库入口访问，不作为可编辑私人歌单展示；Key 授权选择仍保留全局曲库。

### 3. 上传任务

流程为“添加文件 → 校验与预览 → 确认入库”。

- 顶部提供选择文件、选择文件夹和拖放区域，展示附件匹配结果。
- 队列默认每首一行，展示文件名、标题、状态和错误摘要；展开后编辑元数据、封面、歌词及备注。
- 汇总展示总数、待校验、待确认、失败、完成；批量按钮只作用于对应状态的任务。
- 保留单项校验、确认、移除、失败重试与暂存过期后重新校验；不承诺浏览器断网后自动续传。
- 重复内容明确说明复用已有曲目、不改变原始上传者及管理者、不覆盖已有元数据；已下架重复内容提示联系管理员。
- 切换页面保留当前任务；刷新或离开会丢失本地待上传内容时提前提醒，浏览器支持范围内提供离开保护。
- 退出登录后释放本地预览资源、清理账户队列，不把前一个账户的暂存任务交给下一个账户。

### 4. 播放器接入

使用“API Key”“调用统计”两个页签，连接配置说明与 Key 管理放在同一区域。

- Key 列表展示名称、授权范围、状态、最近使用与操作；完整密钥不出现在普通列表。
- 创建时清楚区分全局曲库、指定本人歌单和暂不授权，默认仍为空授权。
- 空授权可以创建，但保存前后明确说明“可以连接，曲库为空”，不把空授权显示为认证失败。
- 一次性结果弹窗提供完整 Key、服务器地址及播放器配置步骤，地址根据当前访问方式给出并允许核对，不将 localhost 当作通用局域网地址。
- 复制成功提示“已复制到剪贴板”，约 2 秒自动消失，无确认按钮；失败选中完整内容并提示手动复制。
- 关闭一次性弹窗后清空完整 Key；如需连接检查，仅使用本次输入的完整 Key，不在浏览器持久化，不把 Key ID 当作密钥。
- Key 新增、改名、撤销与统计范围同步；账户停用保留原统计，重新启用沿用仍有效的同一 Key。
- 本人统计始终只看本人。管理员全站或指定账户统计由管理概览、用户详情进入，页面明确展示当前统计范围。

### 5. 管理概览

- 展示账户、曲库和资源的可用摘要，以及正在执行的扫描、缺失文件等待处理状态。
- 提供用户管理、扫描状态、曲库恢复和系统设置的跳转入口，不在首页堆放完整维护工具。
- 全站统计明确标记范围，不与管理员本人的播放器统计混用。
- 摘要缺少对应接口时先使用已有数据或明确不展示，不用局部数据推算全站计数。

### 6. 用户管理

- 列表展示登录名、显示名、角色和启用／待改密状态，提供创建用户及详情入口。
- 用户详情包含基本信息、当前管理曲目、原始上传曲目、私人歌单、API Key，保留现有资源分页。
- 在用户详情提供显示名修改、密码重置、停用／重新启用和指定账户统计入口。
- 创建与重置后的临时密码单次展示，关闭清空；异步刷新失败不能导致临时密码尚未展示就丢失。
- 管理员查阅他人歌单时始终显示所属账户，不将其加入“我的歌单”或本人 Key 可授权范围。
- 资源接管仅在已停用源账户显示，流程为选择资源、选择接收账户、核对数量和影响、确认。
- 接管前说明 Key 不转移、原始上传者不变、重新启用不自动返还；失败或版本冲突不能假装部分成功。

### 7. 曲库维护

- “目录扫描”集中提供快速扫描、完整校验扫描、进度、结果和取消。
- “文件缺失”展示实际文件不可用状态，避免与主动下架混淆。
- “已下架曲目”展示下架记录与恢复入口；恢复沿用原 UUID、归属和歌单关联。
- 主动下架使用统一名称，说明保留文件与歌单占位，不展示物理删除能力。
- 恢复失败、扫描失败和取消结果在本页面持续展示，不被普通成功通知覆盖。

### 8. 系统设置与个人账户

- 常规页签：媒体目录只读说明、音频探测工具、上传限制、外置歌词及封面扫描设置。
- 备份页签：创建数据库备份并展示实际结果，明确媒体文件需要单独备份；不虚构现有接口未支持的备份列表或在线恢复能力。
- 更新页签：更新仓库、当前版本、检查／下载状态、包路径及已有备份信息；下载完成不等于已安装。
- 操作记录页签：默认摘要列表，按需展开变更详情，不直接铺满原始 JSON；查询范围以现有接口为准。
- 账户菜单：修改密码、查看／撤销登录会话、退出登录。改密后的重新登录、账户停用后的失效处理遵循原有服务端规则。

## 五、统一交互与状态规则

| 情况 | 展示与逻辑 |
| --- | --- |
| 普通成功 | 操作附近或统一通知区显示简短反馈，自动消失，不弹确认 |
| 输入校验错误 | 对应字段旁提示，保留已填写内容，阻止重复提交 |
| 请求失败 | 当前表单或任务内显示原因；有可行重试方式时提供重试 |
| 版本冲突 | 保留用户输入，提示重新载入并核对，不静默覆盖、不盲目自动重放写请求 |
| 未登录或会话失效 | 返回登录，清理当前账户敏感状态；不把失效当作空数据 |
| 无权限或不可见对象 | 沿用后端可见性约定，提供返回入口，不泄露私人资源存在性 |
| 危险操作 | 确认目标、数量和影响，提交中禁用按钮；普通保存不额外确认 |
| 列表状态 | 区分加载中、无内容、筛选无结果、读取失败；失败时不显示误导性的“暂无数据” |
| 持续任务 | 进度与最终结果保留在任务页面，切换页后可返回查看 |
| 批量选择 | 明确选中范围，筛选或翻页时不产生用户看不见的危险选择 |
| 键盘与移动端 | 有可见焦点、输入标签、菜单关闭与返回操作，不依赖右键和拖拽 |

通知与弹窗管理须支持连续操作，后来的成功提示不能隐藏先前尚待处理的错误。与账户关联的缓存、详情、播放器和一次性凭据在退出或切换账户时统一清理。

## 七、阶段任务与验收

所有开发任务初始保持未完成；编写计划不代表完成页面或功能。

### 第一阶段：导航、页面骨架与公共交互

- [x] P01：统一命名、分组导航、角色入口、默认首页和账户菜单，所有现有功能都有明确去处。

## 八、验证方式与交付规则

优先运行与本阶段行为直接相关的回归。纯样式调整以实际浏览器检查为主，不为可逆样式编写机械测试；路由、权限、上传状态和错误处理使用有意义的行为回归。

计划使用的检查入口：

```powershell
# server/ 目录，使用项目可用的 Go 环境
go test ./... -count=1 -timeout 120s
go vet ./...

# 仓库根目录；浏览器用隔离编译程序、临时数据库和测试账户
# MUSIC_SERVER_TEST_BINARY 指向隔离编译程序，MUSIC_SERVER_PLAYWRIGHT 指向可用驱动
# MUSIC_SERVER_TEST_PYTHON 指向可用 Python；驱动路径及 LAN IP 使用当前机器实际值
node server/tests/management-ui.cjs

# 如涉及上传本地预览行为
node --test server/tests/local-preview.test.cjs

# 文档与改动检查
git -c core.whitespace=cr-at-eol diff --check
```

- `management-ui.cjs` 联合现有成员与管理员浏览器脚本完成验收；使用 `MUSIC_SERVER_UI_LAN_IP` 复跑实际非安全 HTTP 上下文，不用 localhost 代替局域网兼容验证。
- 浏览器按桌面及手机视口检查，关注菜单、弹窗、长标题、长歌词、列表溢出、底部遮挡及键盘焦点。
- 测试使用临时账户、临时数据库和隔离进程，不读取个人完整 Key、不写真实剪贴板、不将测试数据放入发布包。
- 每项实现并通过对应验收后，才将 `- [ ]` 改为 `- [x]`；记录命令、结果和未验证限制，与代码及回归一同创建本地提交。
- 最初的计划创建不代表开发完成；后续实施必须经过用户授权，并在对应验收通过后更新任务，不因计划存在而擅自重启服务。
- 按阶段检查相关测试，最终交付完成完整 Go 与浏览器回归；生产路径更新前使用已验证产物，不声称下载、编译或替换等于运行验收。
- 提交不包含密钥、密码、数据库、媒体、日志、测试输出、构建产物和归档；未经用户要求不推送远程。
