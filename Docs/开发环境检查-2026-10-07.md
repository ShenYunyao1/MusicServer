## 当前阻塞项

### 1. MusicPlayer2 缺少 MFC

构建命令：

```powershell
MSBuild.exe MusicPlayer2.sln /t:Build /p:Configuration=Debug /p:Platform=x64
```

结果：`MSB8041: 此项目需要 MFC 库`。检查 `VC\Tools\MSVC\14.44.35207\atlmfc` 不存在，说明 Build Tools 和 Professional 实例均未安装所需 MFC 文件。

需要在 Visual Studio Installer 的“单个组件”中安装：

- **适用于最新 v143 生成工具的 C++ MFC (x86 和 x64)**，英文名称为 **C++ MFC for latest v143 build tools (x86 & x64)**，组件 ID 为 `Microsoft.VisualStudio.Component.VC.ATLMFC`。
- 同时确认 **MSVC v143 x86/x64 build tools** 和 Windows 10/11 SDK 已选中

安装后重新运行上述构建命令。无需安装完整 IDE，Build Tools 也可以完成命令行构建；若使用调试和资源编辑，Professional IDE 会更方便。

安装器搜索框请只搜索 `MFC`。中文名称不包含 `MFC for v143`，使用该搜索词会过滤掉最新组件，只显示部分旧版。不要选标注“不受支持”的旧版或 ARM/ARM64 项。用户正在修改 Professional 实例：安装后应使用该实例的 MSBuild 验证，而不能继续使用未安装 MFC 的 Build Tools 实例。

### 2. Go 已安装到独立目录

已按用户要求下载官方 Windows amd64 压缩包，校验官方公布的 SHA-256 后安装到 `D:\Develop\Runtimes\Go`。`go version` 确认版本为 `go1.27.1 windows/amd64`，`go env GOROOT` 确认根目录正确。未修改系统或用户 PATH，当前可使用完整路径执行：

```powershell
& 'D:\Develop\Runtimes\Go\bin\go.exe' version
```

下载的压缩包保留在 `D:\Develop\Runtimes\go1.27.1.windows-amd64.zip`。需要终端直接运行 `go` 时，可把 `D:\Develop\Runtimes\Go\bin` 加入当前会话 PATH。

### 3. Docker 引擎未运行

Docker CLI 存在，但 `docker version` 无法连接 `dockerDesktopLinuxEngine`。运行服务器容器前需要启动 Docker Desktop 或配置其他 Docker daemon。

### 4. ESP-IDF 没有加入当前终端 PATH

ESP-IDF 文件已经存在，版本为 v5.2.2。开发 ESP32 时应使用 ESP-IDF 的导出脚本/初始化脚本启动专用终端，不建议手工复制大量工具路径到全局 PATH。

## 非阻塞项

- `MusicPlayer2` 依赖的 BASS、TagLib 库文件已随仓库提供，不需要额外下载。
- 本阶段不需要立即准备云主机；本地 Docker 或直接运行服务器即可验证 API。
- 暂不需要安装数据库服务器，SQLite 可作为服务器 MVP 的默认数据库。
- ESP32 音频播放还需要实际硬件：ESP32-S3-N16R8、I2S DAC/功放、扬声器，以及用于缓存的 SD 卡或外部 Flash。

## 推荐准备顺序

1. 安装 Visual Studio MFC 组件并完成 `MusicPlayer2.sln` Debug x64 构建。
2. 使用已安装的 Go 创建服务器最小 API 和 SQLite 数据库。
3. 启动 Docker Desktop，准备服务器的容器化测试环境。
4. 实现 MusicPlayer2 的“设置 → 服务器”和“媒体库 → 服务器”界面，验证与服务端的同步和缓存播放。
