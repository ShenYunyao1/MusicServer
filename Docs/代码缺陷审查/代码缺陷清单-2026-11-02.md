## 四、已排除的误报方向（本轮阴性结论）

- **认证/授权与 CSRF**：Cookie 与 API Key 不混用、失败不回退；Key 的 role 恒为 `player` 且非 GET/HEAD 受 `playerEndpoint` 限制；`/admin/*` 均要求 `requireAdmin`，多数还要求 `requireAdminActor`；强制改密账户拒绝 Key 认证；跨账户读写暂存（`.staging`、`upload_staging`）在 HTTP 层与 store 层均有 `user_id` 双层校验；未发现越权读写他人歌单/Key。
- **路径穿越**：媒体读取使用 `os.OpenRoot` + 相对路径；备份路径 `validBackupPath`、归档名 UUID 校验、tar 只接受命中清单的 `TypeReg`、大小 + SHA-256 + 尾部多余字节校验、解包到临时目录再 rename；未发现 `..`/符号链接逃逸或任意写。
- **XSS**：两轮独立前端审查确认动态 `innerHTML` 均经 `txt()`（转义 `& < > " '`）或改用 `textContent`/`createElement`；歌词、队列、详情文本一律 `textContent`；未发现可证实的注入点。
- **签名更新链**：本轮复读 `internal/update/*`（`update.go`、`install.go`、`protocol.go`、`capabilities.go`、`refresh_worker*.go`、`cmd/musicserver-updater`）：Ed25519 验签、包大小/SHA-256 双重校验、tar 白名单、queue 路径 `os.OpenRoot`、回滚时程序/数据库版本配对、HTTPS-only 跳转均自洽，未发现新的可远程绕过点（仅 B-71 的锁内 I/O 一项）。
- **隐私与状态机**：公开/邀请/Key/sync/SSE 各路径剥离 `track_ids`/`notes`/`lyrics`/`path`，未发现私有歌单与私人备注泄漏；owner 停用/删除/转私有后的授权暂停与恢复、邀请状态机（accept 需可用、幂等、撤回后订阅 invalid）、Key 授权随退订清理、tombstone 防 ID 复用均核对通过。
- **标签 SQL 构造**：筛选/分面 SQL 全部是常量片段 + 占位符（`compileTrackFilter`、`filterVisibleLink`、`dictionaryWhere`、排序白名单），Total 与页查询共用同一 WHERE；未发现注入或计数不一致。
- **播放队列（v0.21.13 新增）**：`source` 鉴权、系统歌单拒绝、`track_ids`/`track_notes`/`unavailable_track_ids`/`lyrics` 剥离、`If-Match` 版本号与 `409 BROWSE_RESTART` 语义、跨页续接与取消旧请求均核对通过。
- **平台构建约束**：`diskspace/space_linux.go`、`space_windows.go` 依赖 GOOS 文件名后缀而非显式 build tag，属正常 Go 约定，不是缺陷。
