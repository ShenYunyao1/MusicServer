# 曲目标签与组合筛选开发计划

日期：2026-10-27，P06 本地验收更新于 2026-10-28。基于服务器 0.20.2／SQLite schema 7、播放器 0.4.0。用户已同意方案并授权按阶段开发，并明确升级保留旧数据；本地进度及验证见第九至十四节。本轮不推送、不发行、不部署云端。

本期实现人工与元数据辅助的标签整理、组合筛选和保存筛选条件。外部资料补全、智能歌单、音频模型与 AI 调用筛选单独记录在 [未来功能规划](未来功能规划.md)，不作为本期验收条件。开发、提交及发行按 [开发提交与版本发布流程](开发提交与版本发布流程.md) 执行，完成并验证后才勾选功能。

## 二、现状与目标

当前 `Track.Genre` 为单值文本；`browse.go` 的关键词搜索覆盖标题、歌手、专辑和风格，基础范围含全部／本人上传／本人管理／未加入本人歌单／缺失文件。已有服务端分页、修订号和对象增量协议可以复用，目前没有独立标签、标签词典、分组筛选及保存条件。

本期目标：同一曲目可以按多个维度分类，公共曲库与个人整理分别维护，支持快速批量标记和一致的跨页筛选。所有关联继续使用曲目 UUID，不因标签变更生成新曲目、不改变原始上传者、不修改原音频或重算文件摘要。

## 三、标签与权限

| 分组 | 示例 | 默认使用建议 |
| --- | --- | --- |
| 风格 | 流行、摇滚、电子、古典 | 公共分类，可多选 |
| 演唱语言 | 汉语、日语、英语、无演唱 | 公共分类；未知时留空 |
| 版本 | 现场、翻唱、重混、伴奏 | 公共分类，可多选 |
| 情绪 | 舒缓、激昂、伤感 | 个人整理为主 |
| 场景 | 通勤、学习、夜间驾驶 | 个人整理为主 |
| 自定义 | 待整理、练琴参考、婚礼候选 | 个人整理 |

以上为起始分组和示例，不把示例标签强制分配给曲目，也不要求每组必填。“演唱语言”指实际演唱语言，不直接采用标题文字、歌手国籍或专辑资料语言推断；未知、待确认与无演唱分别表达。

- 公共标签：对有权读取曲目的用户可见。曲目当前管理者和管理员可选择、添加或移除该曲目的公共标签，沿用管理权限；原始上传者字段不因此改变。
- 公共词典：由管理员维护标签名称、别名、合并及分组。导入或普通成员输入的未知词不能无约束创建公共词条，保留原始值并提供待归一提示；管理员确认后才进入公共词典。
- 个人标签：用户可为自己有权访问的曲目创建、添加和移除，只对本人可见、可筛选。分组表的默认建议不限制个人使用其他分组。
- 个人标签和保存的条件不进入其他用户、公开歌单投影、共享缓存或播放器通用曲目对象；本期不开放个人标签的播放器 Key 接口。管理员管理公共曲库不等于可以浏览别人的私人整理内容。
- 停用账户保留私人整理数据但禁止访问；恢复启用后可继续使用。删除账户清理其个人标签、关联和保存条件；曲目接管保留公共标签，不把个人标签转给接管者，其他用户对该 UUID 的个人整理保持。
- 标签编辑属于普通资料整理，沿用登录、首次改密及管理权限规则；不新增邮箱上传资格要求，不改变音频配额。真正上传音频及附件仍执行现有校验。

标签使用稳定 ID，名称与别名可调整。唯一性规则覆盖作用域、所有者和分组；明确 Unicode、首尾空白及大小写归一规则，不以名称子串判断标签相同，不把含义不同的风格自动合并。设置标签长度、每曲目标签数、个人词条数、请求大小及批量任务上限。

## 四、打标交互与导入

1. 上传时：整批设置默认标签，可逐首调整；先预览，确认入库时一并应用。仅编辑标签或取消预览不会创建曲目关系。复用去重曲目时，仍按现有 UUID 和管理权限处理，不能因为重复上传就改写他人的公共标签。
2. 单曲整理：曲目详情区展示标签、所属分组及公共／个人属性，进入编辑器修改；点击标签可打开对应筛选。列表只显示少量标签和其余数量，详情可展开全部，避免撑高每行。
3. 批量整理：多选后右键“管理标签”，支持添加／移除；显示共同拥有和部分拥有的状态，未操作的标签保留。提供键盘菜单及移动端长按入口。
4. 选择范围：明确区分“当前页”“已选曲目”和“全部匹配结果”，展示数量和将修改的作用域。跨页任务冻结预览确认的曲目 ID 集合，运行期间新增匹配项不被悄悄纳入。
5. 事务与任务：普通有界请求按对象版本全有或全无；冲突保留草稿并提示重新读取。大集合采用有界后台分批任务，逐批复核权限、会话和版本，记录已完成／冲突／失败，不把分批任务宣称为全库原子操作。账户停用或会话撤销后停止后续写入，支持查进度、取消及幂等重试。

元数据辅助仅使用现有文件中可明确读取的字段：先导入风格，识别格式本身提供的多值结构，按公共词典和管理员别名映射；保留原 `genre` 作为来源及旧客户端兼容信息。其他字段只在含义明确时扩展，不从文本猜测情绪或场景。

导入、人工确认和人工移除需有可区分的来源／覆盖记录：重扫可更新未被人工覆盖的导入结果，不能覆盖个人标签、抹去人工确认，或自动重新添加人工已明确移除的标签。禁止用一个通用分隔符拆分所有字段，例如不能把 `AC/DC` 拆成两个歌手。

本期所有打标、词典处理和分类索引均与昂贵分析解耦，不给现有上传校验额外增加外部请求或音频模型计算。标签修改只更新数据库，不回写源文件。

## 五、组合筛选与页面布局

曲库顶部保留搜索；常用范围和筛选入口直接显示，复杂条件放筛选抽屉。当前条件以可单独移除的标签块展示，区域位置稳定；右键操作不插入顶部操作栏、不推动列表整体下移。移动端使用同样的条件模型，抽屉适配窄屏。

本期条件包含：公共标签／个人标签与分组、歌手、专辑、曲目格式、时长、本人上传／本人管理／管理员可用的上传者筛选、未加入本人歌单、歌词／封面状态、未标公共标签和未标个人标签。未分类不等于未知风格，也不等于别人没有个人标签。

默认同组任一匹配、跨组同时满足；高级选项支持全部标签匹配和排除。显式表达作用域，例如：

```text
公共风格（摇滚 或 电子）
且 演唱语言（日语）
且 我的场景（通勤）
且 排除公共版本（现场）
```

- 搜索、筛选、排序、结果数量与分组计数在服务端完成，不能只对当前页过滤。排序采用字段白名单和稳定的 UUID 次序作为末级排序，确保分页一致。
- 标签选项提供搜索、有限分页和条件下数量；计数先应用当前账户的访问范围及其他条件，再统计当前分组，不泄露私人词条或不可见资源。
- URL 保存可恢复的筛选、排序及页码；返回曲库、刷新和复制地址后仍复原条件，但读取始终重新检查当前账户权限。
- 个人筛选条件保存名称、结构化条件及版本，支持重命名、删除与应用。引用删除或合并的标签时，明确提示／解析合并结果，不能静默丢条件后扩大结果。
- 第一版保存条件只保存规则，不创建／修改歌单、不自动给 Key 授权；智能歌单在未来规划单独实施。
- 输入防抖、过时请求丢弃、权限相关缓存键及修订检查沿用现有模式；失效条件、空结果、网络错误和重试状态可区分。

## 六、数据模型、迁移与更新前提

推荐独立关系表及索引，概念模型为 `tag_groups`、`tags`、`tag_aliases`、`track_tags`、表达人工覆盖／忽略的记录，以及 `saved_track_filters`。标签与曲目多对多；来源及作用域可被查询，个人关系强制绑定账户，常用筛选建立组合索引。最终 DDL、容量边界和具体索引在 P01／P02 确认，不把关系查询长期混入通用 `meta` 文本中。

新增 SQL 表需要显式 schema 升级，目标暂按 7 → 8 规划，实施前核对最终版本号；`version.Schema`、`PRAGMA user_version`、数据库元数据、签名发行清单和健康接口必须一致。

当前存在两条真实限制：`sqlite.go` 拒绝非当前非空 schema；独立更新器 `install.go` 拒绝清单与已安装程序 schema 不同。网页更新不会自动替换独立 root 更新器。因此 P01 必须先明确：

- 已发布 0.20.2 的升级路径及独立更新器的受控升级方式；如需引导版本，明确其仍使用 schema 7 的职责和安装顺序。不能只发布 schema 8 主程序就声称现有网页能直接一键升级。
- 非空 schema 7 库的事务迁移、重复启动幂等、迁移中断恢复、旧库备份及新旧备份恢复路径。保留曲目 UUID、媒体路径、音频摘要、账户、Key／授权／统计、歌单／订阅／邀请、邮箱状态和配额，不清库重建。
- 停服、快照、迁移、健康检查和失败回退的顺序；新库不能交给不认识它的旧程序，失败时恢复与旧程序匹配的数据库快照和程序。
- 更新器仍验证签名、版本与明确的兼容迁移范围，未知／不支持的 schema 拒绝并提示；不直接删除兼容检查。
- 新权限边界和更新器／系统文件变更须另行获得实际云端维护授权；本次记录计划不授权 SSH 或替换 root 工具。

P01 的兼容方案和恢复验证通过前，不将带新表的标签版本作为可直接云端升级的正式版发行。

公共标签变更只通知受影响曲目或词典；个人标签及个人条件使用账户范围的版本和通知，不触发其他用户的公共对象变更。标签重命名不改变曲目 UUID、音频缓存或歌单成员。旧播放器可继续使用原曲目／歌单协议，公共新增字段的兼容性需要真实测试；本期不修改播放器界面。

## 九、P01 本地实施与验收（2026-10-27）

本阶段交付 schema 7 桥接基础，`version.Schema` 仍为 7。正常启动、备份及恢复不产生 schema 8 库；通过包内私有目标接口演练 7→8，当前仅建立迁移账本。P02 必须在首次启用／发行 schema 8 前补齐最终标签 DDL，不将演练库当成已发布的 schema 8 格式。

### 已实现

- `internal/version/schema_policy.go` 明确只认识 7／8 及单向 7→8；未知、反向、自迁移声明拒绝，不由清单任意扩大支持范围。
- `internal/music/schema_migrations.go` 和 `sqlite.go` 提供事务注册、双 schema 身份核验、幂等及完整回滚。非空旧 7 库的原表、UUID、Key、私密元数据、邮箱、配额、订阅、邀请、统计和同步秘密原样保留；未知旧库拒绝且不修改原文件。
- 备份生成核对实际库身份，恢复先核对归档声明、PRAGMA 与 meta，再迁移到受支持的目标。失败不发布目的目录；保留既有恢复时的路径重写、会话／暂存清理、同步秘密轮换和邮件安全重置。
- 签名清单／包内身份增加可选 `migrate_from`，schema 7 包保持省略。应用检查、排队及 root 安装器都复核迁移路径；安装器核验源备份与旧程序身份，升级、健康失败及中断均按源 schema 恢复程序和快照。
- root 能力文件验证所有者、父目录、权限、普通文件及无链接；未安装的候选不能提前自报。普通运行和能力发布核对实际执行文件与独立安装位置的 SHA-256 一致，维护完成后才发布新能力。
